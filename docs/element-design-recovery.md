# Element-scoped recovery and photo inspection

This October 23 policy supersedes earlier wording limiting visual work to one call or requiring a whole-layout fallback. It changes only private generation/review/rendering within the current run. It never authorizes retries of an API error, authentication failure, dispatch, storage write, cleanup or publication.

Before overlay, inspect the actual complete photographs and exact feed crops for clear major anatomy/object defects, scene mismatch, unusable geometry or unwanted lettering. Natural occlusion, deliberate cropping and depth of field are not missing anatomy. The inspector sees only the original scene and public quiz question/options, never an answer key or styled references. Only a fixed defect verdict can trigger another FLUX generation, with a fresh private cache namespace and an optional scene-only replacement prompt preserving the task and secrecy. There are at most three actual photos per card, including the initial one. Stop at an accepted photo. If all three have flagged defects, retain the highest-rated photo (latest wins a tie), its exact prompt and its own original cache reference, and report best_effort with the unresolved fixed defect reason. A failed inspection service is not a defect verdict and is not retried. Explicitly retained same_image photos are inspected but never silently regenerated; exact same_image&design cards stay intact.

Pillow first checks the approved declarative design with all existing exact-copy, glyph, contrast, bounds, header/logo, photo protection and collision checks. Recoverable layout failures are isolated to named elements: body, example, each answer, category, heading, photo window or overall design family. Valid sibling blocks and global elements remain exact. A bounded measured position repair may translate only the failing elements. The search uses the requested coordinates as its target, not the default template's anchors, and does not claim global geometric optimality or semantic object detection.

If a design still needs repair, give ChatGPT the same actual photo/crop, exact text, safe rejection reason, previous approved parameters and locked accepted elements. It may correct only the failed elements; changing a locked element is rejected. There are at most three design proposals per card, including the initial proposal. A service failure stops repair calls without another request. After exhaustion, use measured local recovery only for the smallest failing element set. Retain as much safe style, colour, width and typography intent as possible and find the nearest tested valid position. Recheck the complete composition and actual pixels so a replacement cannot collide with a retained block. Full deterministic fallback is reserved for unavailable/uncertain/untrusted structures or when no safe partial composition can preserve any element. An unreadable/unrenderable final fallback still stops publication. Palette provenance remains independent; a valid palette is retained when individual element recovery can solve a contrast problem.

Per-card reports distinguish chatgpt, mixed, reused and fallback layouts and independently identify palette provenance. Mixed reports name the preserved and replaced elements. Report design attempt results and photo inspection/selected-attempt status using fixed safe enums/reasons only. Do not claim that a rejection followed by successful repair was a full-layout fallback. No model prose, credentials or answer keys go to reports.

## Exact finished cards in custom selection

Each word action offers same_image&design alongside keep_today, same_image, chatgpt and entered. It keeps that role's exact reviewed source card, word metadata, original photograph, feed JPEG and Story JPEG. Other selected slots and the caption can change. A retained quiz keeps its reviewed choices/count/private answer metadata, and all public answer-secrecy checks still apply to the new batch. Leave the typed word field empty.

The trusted wrapper seals rendered_sources; model drafts must omit rendered_sources, background_source and background_sources. Snapshot references bind source copy and the exact image bytes in the existing admin-only 14-day asset cache. These are expiring cache provenance, not history rows, reservations or publication state. New snapshots are referenced by history only after confirmed feed publication; preview and failed generation never save novelty. Reuse preserves original expiry. Missing, expired, altered, incompatible or ambiguous source files stop before cleanup instead of silently replacing a pinned card.

Older rows without snapshots can be imported only from a retained private artifact associated with a recorded confirmed feed ID and exact byte-for-byte reproduction from its approved composition/source. Similar-looking cards or a mutable latest filename are insufficient. If proof is unavailable, report that exact reuse is unavailable.

The one existing workflow allows 60 minutes for bounded in-run work. Scheduling, credentials, dispatch, cleanup, publication safeguards, history lifecycle and Story treatment B remain unchanged. No extra live post is used for testing.

A confirmed FLUX content-safety/NSFW refusal may trigger a tool-free ChatGPT rewrite of the benign educational scene and another inference request in a fresh artwork namespace. Preserve subject/task/secrecy and natural photographic rules; never bypass safety filters or repeat an unchanged prompt. NSFW refusals and defect-driven generations share THREE TOTAL inference attempts per card. Other API/service/auth/quota/capacity errors and prompt-rewrite failures stop immediately. A pinned photo is never regenerated. If no image was returned after the budget, fail clearly; when an earlier actual candidate exists, keep its best inspected version and report the refusal/budget. Final selected prompt and matching cache provenance must remain exact. Reports distinguish inference attempts/refusals from photo inspections.

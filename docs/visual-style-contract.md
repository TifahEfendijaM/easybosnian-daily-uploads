# Trusted visual rendering contract

ChatGPT selects approved data after inspecting the generated photographs. Pillow validates and draws the exact source. No visual child ever writes drawing code or changes copy.

## Allowed data

Each card has `confidence`, `design` (`hybrid` / `editorial`), an approved `palette` ID, `category_style`, `heading_tone`, `photo_window` and ordered `blocks`. Older local plans may omit the new fields and receive trusted defaults. Palette IDs come only from `data/design-palettes.json`. A photo window is null or `{y, height, fit}`: x64/width952 are fixed, y250–770, height400–800 (240–800 for visual-identification quizzes), fit `contain` for hybrid or `cover` for editorial. Full-background hybrid uses the feed crop. A contained photo remains complete; an editorial cover crop requires a visual assessment that required subjects survive.

Each block allows only `role`, `style`, `x`, `y`, `width`, `font_size`, `line_spacing`, optional `max_lines` (null or1–12) and `wrapping` (`balanced` or `natural`). Answers additionally allow `marker_style`: circle, rounded_square, square or triangle. Body/example roles cannot supply this field. All text comes from the exact reviewed card; there is no text field in the proposal. Blocks preserve source order and every role. Examples additionally allow `photo_tone` from the photographic colour enum. Bodies/answers cannot supply it. Bodies/answers additionally choose `panel_opacity`: a numeric percentage from 50 through 100 inclusive (fractional percentages allowed). Plain editorial body accepts only 100 because it has no panel; examples cannot supply panel opacity. Labels/title typography and anchors stay renderer-controlled.

| Role | Font targets | Face | Leading |
|---|---|---|---|
| body | 32–48px | bundled Inter Regular | 1.20–1.55 × font size |
| answers A–D | 32–46px | bundled Inter Regular | 1.20–1.55 × font size |

Leading must additionally leave at least4px between measured full accented glyph bounds. Pillow computes height; the model cannot specify height or replace text with manually line-broken copy. `max_lines` rejects overlong exact text rather than truncating it. Natural wrapping is greedy; balanced wrapping distributes the minimum number of lines without tiny orphan lines. Unicode spaces preserve exact reconstruction; NBSP, narrow NBSP and word joiners remain unbreakable. Diacritics and combining characters are never stripped or normalised for drawing.

## Separate PRIMJER enum

Only `italic_photo`, `italic_photo_fade`, `italic_footer` are valid. All use Lora Italic and a small renderer-owned PRIMJER label, never a box. `italic_photo` uses the photograph directly and fails if glyph contrast is insufficient. `italic_photo_fade` may apply the original fixed neutral or palette-coloured feathered contrast presets. The model chooses only an approved text/fade colour pairing, never alpha, filter, fade geometry or strength. `italic_footer` uses the editorial paper below the photograph with a thin separator. Stories use an unboxed italic paper footer.

## Independent trusted checks

The JSON schema rejects extra fields, mixed role/style enums, invalid typography and unapproved palette/design/window choices. Pillow reloads actual fonts, wraps exact text, measures glyph extents/final height and rejects clipping, leading collisions, overlap, lost/reordered roles or unsupported design combinations. Blocks stay within x64–1016, below the measured heading+24 and above y1170. Editorial examples alone may end at y1286, with right edge<=880 to protect the logo. Visible blocks need8px separation (14–24px preferred); editorial body/photo/footer need24px gaps. Hybrid photo examples must stay20px inside the actual contained photo. Body/answer treatments cannot overlap a separate photo; opaque/semitransparent panel coverage cannot exceed49% of the card. Full-background subject recognition is a visual judgment; geometric protection does not claim to detect arbitrary faces/objects.

Body/example glyph contrast is at least4.5:1; title contrast is at least3:1. Photo-text contrast is sampled at actual glyph-mask locations against the final composited surface, including neighbouring preset fades. Approved palette ink/paper/accent contrast is checked. No proposal may supply drawing primitives, replacement text, code, CSS, font paths, custom hex colours, fade alpha, panel opacity outside 50–100%, borders/radii/shadows or arbitrary filter definitions.

Layout and palette are independently accepted or replaced. The model-facing JSON contract remains strict; the trusted wrapper replaces only a missing/unapproved/low-contrast palette with the preparation palette and validates every other field unchanged. An invalid non-palette card field rejects that card’s entire layout, preserving valid sibling cards and its independently approved palette. Malformed top-level JSON or card-envelope structure still discards the whole review. Unavailable review uses both defaults; uncertain confidence replaces the layout but keeps a valid model palette. A measured layout failure replaces all layout fields together while preserving a valid palette. Photographic palette contrast failure validates the exact same layout with the preparation palette; only if that still fails does the layout also fall back. Only bounded, reported position translations may be repaired under the October 20 policy below; typography, tone, style and copy stay exact. Every accepted combination must pass all the same glyph, geometry and final-pixel contrast checks. This is bounded local Pillow fallback, never a second model/FLUX/storage/publication call. The fallback keeps the body under the heading and places PRIMJER near the lower safe edge (target bottom y1150), moving upward only as exact measured height requires. If the fallback cannot preserve exact text and readability, the run fails before publishing. Integrity failures remain fatal. Stories keep treatment B and select the matching feed card's final approved palette. Final safe data is captured in the private placement result and GitHub report; no raw model prose is logged.

Legacy `design_template` remains readable but ignored, has no effect on bytes, and is absent from newly saved content. Rendering manifest version19 prevents reuse of artwork from the earlier panel-rendering contract. No Worker/database/scheduler deployment is required. Repository merge activates this contract for subsequent runs.

Quiz composition: every answer has independent x/y/width, approved panel style and bounded typography. Ordinary choices may be staggered across left/right and upper/middle/lower regions, preserving A/B/C/D reading order and measured visibility/fit. Do not treat them as a single stack or mechanically stack them. Each answer may independently choose marker_style=circle, rounded_square, square or triangle. Coordinated styles/badges are a preference, not a hard rule; mixtures are allowed when the image looks better. All colours remain from the image's approved palette; never highlight an answer as correct. Visual-naming quizzes keep the complete photograph protected with all choices below. Badge shapes are trusted Pillow presets, not model drawing primitives. For neighbouring answers intended as a shared row, choose exactly the same y and coordinated font_size/line_spacing, avoiding tiny accidental offsets. Pillow uses a shared measured font cell for answer heights and baselines, including Bosnian accents and descenders; equal typography and line counts therefore align. Different line counts may require different heights. Deliberate staggered arrangements stay available with clear spacing and label reading order; do not automatically snap independently placed choices into a grid.

Editorial category tracking uses one shared capital baseline; Š and Č retain their accents above the capitals instead of shifting downward. Rendering manifest version 6 invalidates earlier prepared labels.

Ordinary lesson/word feed cards prefer the full photographic background with separately placed approved body and italic example treatments. Separate middle photo windows are a less-frequent alternative, mainly when long exact copy or important photo subjects make a readable/elegant overlay difficult. Visual-identification quiz photo protection remains unchanged. Stories use treatment B with a thin palette-accent rule above PRIMJER, which remains unboxed Lora Italic.

Full-background hybrid is the strong ordinary-card default. Choose its approved body treatments freely after comparing compatible treatments and plausible independent block placements; the routine model sheet contains only the original photo and exact feed crop, without any styled reference that could bias the choice. Middle windows remain an exceptional last resort when long exact copy cannot fit elegantly or readable overlays would obscure important subjects. This is a content/photo-based preference, not a random selection probability.

The visual reviewer receives only the complete generated photographs and exact feed crops, without any rendered hybrid/editorial style example. Exact public block text and measured heights are supplied as data; quiz answer keys remain excluded. The deterministic default_plan is explicitly an uncertainty fallback, not an example to imitate. The approved catalogue, strict declarative choices, full-photo preference and measured safe fallback remain unchanged.

Before selecting a final treatment for each card, ChatGPT actively reviews all compatible options from the full approved design catalogue, then compares several materially different treatments and plausible placements against the actual photograph, its negative space, exact text length, visual hierarchy, subject visibility and overall balance. Compare recent accepted design metadata from up to five completed daily runs, including reruns; exclude every fallback and never provide rendered references. If a treatment or visually similar family has dominated, prefer a materially different approved alternative that remains suitable, appealing, readable and harmonious, even if slightly less optimal in isolation. Never choose an unsuitable style or palette for variety. Each photograph independently receives its best-fitting approved palette, without a batch-uniformity preference. Recent use breaks ties between suitable choices; it is not a ban, quota, forced rotation or random choice. Repeat when the alternatives are unsuitable. This comparison preserves compatibility constraints, the strong full-photo default, the available middle-photo exception, photo-only review inputs, fallback-only default_plan and all Pillow validation/rendering rules. After inspecting each actual photo, compare suitable upper, middle and lower regions and left/right or split block placements within the protected header/logo bounds. The upper area has no automatic preference. Judge subject visibility, negative space, exact copy, hierarchy and balance, rather than assuming a text-at-top photograph. Top placement remains valid when independently best for that image. No quotas, rotation, randomness or forced positional variety.

FLUX chooses the photograph’s composition. This overrides the original master prompt’s pre-image layout and text-space framing instructions. Write only the relevant scene, subjects/actions, environment, photographic realism, natural light, realistic textures and true-to-life colours. Do not direct subject position, camera framing, negative space, headroom, empty areas or a top/middle/bottom composition for overlays. Do not use measured copy or a guessed text position to shape the photograph. Leave composition to FLUX; the later visual reviewer adapts the approved text design and placement to the actual generated photo. Preserve quiz relevance and task-specific secrecy. Never request panels, coordinates, text, logos or recolouring to fit a palette.

## Approved category and photo-colour choices

Category labels expose six materially distinct treatments: `rounded` (moderate corners), `pill` (capsule), `ribbon` (pointed right edge), `underlined` (unboxed text and rule), `outlined` (paper chip with accent border), and `tab` (square accent tab and inset rule). All keep the trusted category anchor, Inter font and exact Bosnian accents. The final category choice carries into both IG/FB treatment-B Stories without another model call.

Fresh review `heading_tone` and example-only `photo_tone` expose `paper_dark` (white text/black fade), `ink_light` (black text/white fade), plus approved palette-role pairs `paper_ink`, `ink_paper`, `accent_ink`, `ink_accent`, `accent_dark`, `accent_light` and `paper_accent`. Names indicate text then backing colour; all coloured values come from that image’s selected approved palette. `auto` supports paper layouts and deterministic fallback. Only colour pairing is selectable: photographic fades retain the original renderer-owned shape, extent, edge, strength and contrast-driven application. Fresh JSON accepts neither `heading_fade` nor `fade_style`. `italic_photo` remains unshaded, and paper headings/editorial footers use palette ink. Historical fade-shape fields remain readable for older reports.

Assign each palette ID independently after inspecting that photograph’s natural materials, lighting, dominant colours and readable text/panel contrast. No shared-palette preference applies. Repeated palettes are acceptable when independently best; never sacrifice a better per-image match for batch uniformity or forced variety. The preparation palette remains only a deterministic fallback.

## Safe rejection diagnostics

A renderer rejection writes the exact message only if it belongs to the fixed trusted validation-message catalogue. Unknown messages become an explicit unclassified diagnostic, never raw provider/model prose. Save the rejected proposal only if the strict approved JSON schema validates it: enums, geometry and bounded typography, without source copy, answer keys, credentials or arbitrary instructions. Record these before fallback so they survive even if fallback itself fails. The private per-card rejection artifact, final placement result and GitHub summary/report expose the reason and approved parameters. Preserve all existing fit/contrast/collision/secrecy checks and the one visual-call/no-generation-retry rule.

Each image’s run summary and successful-run report explicitly show separate layout and palette sources and fixed reasons. Either source may be ChatGPT or fallback, including both mixed combinations. Legacy palette provenance is unknown rather than inferred from matching IDs. The old status/outcome field remains a layout-only compatibility field. Recent accepted layouts exclude fallback palettes from model-choice context. Unavailable review, uncertain confidence and measured Pillow rejection remain separate fixed diagnostics; unknown historical reasons are labelled unknown rather than guessed. Recent-design metadata contains only approved final enums from accepted decisions, never images, copy, answer keys, fallback plans or arbitrary model prose. Failure to read recent context does not block the one fresh photo review. No visual repair call, image retry, schedule or persistence table is added.


## Avoiding false visual rejections

The one read-only visual call has a 600-second deadline, without a repair call or retry. Its context includes compact exact-copy fit profiles across representative widths and approved font sizes, deduplicated by measurement family only, including body panels that share identical glyph metrics. Each style ID remains independently available with its distinct renderer. The longer single-call allowance covers occasional slow reviews without a second call, model downgrade or fewer creative choices. Samples include the complete measured height, line count, padding, label and separator. They are measurement data, never styled references, placement recommendations or a restricted design menu. All approved intermediate widths, font sizes, leading and independent positions remain available. The reviewer checks the chosen height against neighbours, protected regions and photo windows before returning its single proposal; it must not scale paragraph heights linearly across different wrapping widths/fonts.

Glyph height follows the exact baselines that Pillow draws. Explicit leading must leave at least four pixels between each actual adjacent pair of rows; one line has no inter-line collision. Paragraph height uses the actual lowest rendered row, rather than assigning the largest descender to every final line. Panels retain their full occupied rectangles. The measured minimum gap is eight pixels, with 14–24px preferred for breathing room; touching/overlapping blocks still fail. This permits the observed valid 10px/12px gaps without moving any model-selected block. Unboxed text collision checks use its visible glyph/label/rule width instead of unused trailing wrapping space; the full declared geometry must still stay inside safe bounds and any protected photo window. Fades still undergo final-pixel contrast validation. Only the bounded, reported x/y translation policy below can adjust positions; typography, style and copy are never repaired or changed.

Per-card malformed layout choices are isolated and reported as `review violated the declarative schema`; they never invalidate safe sibling decisions. That card’s approved palette still survives independently. An unavailable/timed-out call or malformed outer review envelope uses the existing full fallback. Integrity failures remain fatal. No publication, history, scheduling, Worker or automatic-retry behavior changes.

For ordinary quizzes, use four reviewed choices for a deliberate two-by-two grid, aligning both rows and both columns. With three reviewed choices, use an intentional three-card arrangement such as a centred lower card, not an accidentally incomplete grid. The visual stage cannot add a fourth answer or alter answer copy. Two-, three- and four-choice quizzes remain supported.


## Approved panel opacity

After inspecting each actual photograph, ChatGPT selects numeric `panel_opacity` from 50 to 100 inclusive for each bounded body/answer panel. Fractional percentages are allowed. This is a deliberate aesthetic/readability choice based on the local photograph and colour pairing, never a random value. Busy/high-contrast areas may need a higher percentage or 100. It is independent of panel style, placement and answer badge; it does not control photographic fade strength, category labels or treatment-B Stories.

Pillow converts percentages to 8-bit surface alpha, composites only the bounded background, and keeps text, badges and rules opaque. Actual final-pixel glyph contrast must pass. Unsafe opacity is never silently raised; the existing independent layout/palette fallback and diagnostics apply, without another model call or added fade. Plain editorial copy has no panel and requires 100; PRIMJER remains unboxed. Legacy `solid`, `soft`, `translucent` plans remain readable at their former alphas, and omitted opacity retains prior behavior (alpha235 for overlay_light). Fresh model JSON accepts only numeric percentages. Applied-design reports and recent-design metadata preserve those bounded values. Local logo-palette experiments are not a production palette policy.

## Fixed photographic fades and complete catalogue comparison

Free fade-shape controls are withdrawn from fresh visual reviews. ChatGPT may choose only an approved photographic text/fade colour pair: the original white-on-black and black-on-white options plus approved palette ink/paper/accent pairs. It cannot choose dimensions, borders, edge softness, opacity, strength or arbitrary colours. Pillow retains the original fade geometry and contrast-driven strength, applying shading only when needed. Fresh model JSON cannot supply heading_fade/fade_style; legacy fields remain readable for older private reports. Auto remains for paper layouts and deterministic fallback. Bounded body/answer panels independently accept any numeric opacity from 50 through 100 percent inclusive, chosen for the specific photo/readability rather than randomly. Glyphs/badges/decorations stay opaque. Legacy opacity strings and omitted defaults remain readable, but fresh reviews use numbers. Catalogue shapes, placement adjustments and Story treatment B stay unchanged.

Catalogue order is not a ranking or recommendation. Before choosing, compare every approved palette against the actual photo, and review all compatible choices for design family, block style, category treatment, badge, panel colour pairing, opacity and placement. Do not stop at the first acceptable option, choose the last-listed option by habit, or settle on a familiar treatment without completing the comparison. Select the best-fitting combination after that comparison, subject to the existing terracotta-sand alternatives-first rule. No forced rotation, shuffle, unusual-style preference or extra model call is introduced.

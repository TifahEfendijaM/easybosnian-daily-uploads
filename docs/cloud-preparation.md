# Cloud preparation

The existing Cloudflare Worker dispatches preparation.yml at 05:00 Europe/Sarajevo with mode=daily. One ubuntu-22.04 job restores a dedicated cloud-only managed ChatGPT credential, runs the official pinned Codex CLI 0.160.0, saves reviewed content in D1, persists the refreshed credential and renders/publishes immediately afterward. No paid OpenAI API or awake Mac. There is no reusable workflow, queue commit, package handoff or recovery mode.

The research child uses a stripped environment, workspace-write sandbox, live web search, seven-minute limit, private logs, structured ready/blocked output schema and a tracked-file Git diff check. Provider/admin/GitHub secrets stay with the trusted wrapper. It can write unreviewed drafts/private research under build only. Free-form model output and raw events never go into issues or uploaded artifacts. The wrapper requires an actual reviewed draft and validates independently before saving history.

verify checks infrastructure and the child's actual workspace probe. It cannot choose content, write history, call FLUX, render or publish. Preview saves content if absent and otherwise reuses the selected history row; it renders privately. Every daily selection prepares fresh copy, prompts and design choices, retaining theme/words only as selected, then overwrites the selected row. The trusted wrapper enforces exact pinned metadata and narrow same-date novelty exceptions. Known provider IDs are saved separately for deliberate cleanup; they never bind the date to immutable content or suppress a run. After rendering, best-effort cleanup attempts that date's Instagram feed/Stories and Facebook feed posts; deletion errors do not block independent publishing, and Facebook Stories/backing photos are never deleted; TikTok reruns continue without checking or confirming manual deletion; old TikTok posts must be removed manually if desired. See manual-reruns.md.

Credential bootstrap/persistence retains the dedicated temporary auth directory and managed-subscription validation. The workflow's always-run persistence step saves refreshed CODEX_AUTH_JSON with the separate repository-restricted GH_SECRETS_TOKEN, even after preparation fails. Never copy a desktop session, expose a token or use stale auth as a paid fallback.

Use scripts/cloud_auth_setup.py login then save only if dedicated cloud authorization needs renewal. Existing configured credentials remain. The old cloud proof commit/read-back is removed because connection verification no longer needs repository content writes. Safe verification results are workflow artifacts.

DAILY_POSTING_ENABLED is checked before daily preparation and every actual live publisher. verify/preview remain available while disabled. Missing schedules generate no notification. Failures during a run still produce private GitHub issues and build/failure.txt; no Healthchecks or watchdog exists.

Content instructions live in docs/cloud-agent-task.md and docs/preparation-task.md. All learner-visible copy is Bosnian. Quiz photography must be relevant: a pictured object is allowed when identifying it is the task, while images must not solve a hidden fact or reveal a written answer/option letter. Znaš li? prioritizes useful situations, meaningful comparisons and verified interesting facts over routine grammar drills. Translation-template rejection is a deterministic backstop, not a general language detector; the GPT reviewer still checks every public string and scene.

New captions finish with a short, witty Bosnian invitation tied to the batch and 👉easybosnian.com on the final line. The reviewer checks relevance and quiz secrecy; the trusted wrapper enforces the final website line before saving newly prepared content. Existing history/preview content is not retroactively changed.

Four daily selections now include custom inputs. same_words retains theme/words and individual levels but regenerates copy/captions/prompts and reselects palette/layouts; custom regenerates text and captions from requested values even when blank fields reuse the selected batch. The trusted context carries these inputs without expanding the child environment or credential access. Every newly prepared draft must include reviewed quiz_format and the contextual website footer; existing saved previews remain unchanged. fit_check measures both feed and applicable B Story treatments before a history save.

The shared target_cefr is snapshotted from data/preparation-settings.json at preparation time and passed only as structured context. Fresh-text drafts record that exact top-level bosnian_level; same_words retains individual word levels while rewriting copy. Per-word custom actions resolve to pinned metadata or null slots delegated to the research child. Individual word levels govern rewritten copy; retained levels remain, and changed themes delegate keep-today slots. Reviewed thematic incompatibility can replace an entered word under docs/difficulty-policy.md. The child environment remains stripped.

Znaš li? may explain a useful difference between two words or a broader topic, rather than one word. Its heading describes the lesson and need not equal its internal selection seed. For custom Znaš li?, select entered and type a word, a comparison such as “peći / kuhati”, or a short Bosnian topic. The existing second entry stores that seed for selection/history; fresh comparison/topic metadata includes its principal taught lemmas as novelty terms. Retained seed metadata stays exact; the reviewer also checks full previous lesson text. Additional taught terms must respect history novelty and quiz-answer secrecy. New lessons stay source-reviewed, Bosnian-only and measured for both feed and Story fit.

Replacement cleanup selects only the latest recorded batch on the selected Sarajevo date: the last Instagram feed post and up to three Stories recorded after it, and the last Facebook feed post. It leaves earlier same-date batches alone and never fills a partial latest Story batch with older Story IDs. D1 insertion order is exposed as recorded_order in the authenticated ID listing; provider ID sorting is not used as a clock. If order is unavailable, cleanup warns/skips and publishing remains independently gated. Facebook Stories/photos and TikTok posts stay manual. No content history, reservation, intent, retry or daily-claim state is added.

## Batch date across midnight

Manual runs default to batch_target=latest. Resolve the newest complete schema_version=1 history row on or before the current Sarajevo date, regardless of midnight. Retain that row’s original date for selection, complete history overwrite, artwork cache invalidation, publishing ID recording and latest-batch cleanup. Metadata-only imports are novelty history, never a rerun source. If there is no complete row, use the current date; same_words/same_theme still require a source, while new or fully specified/delegated custom can create the first batch. Preview uses this same target and reuses its exact saved content. verify never prepares or publishes.

The automatic 05:00 Worker dispatch explicitly supplies batch_target=today and mode=daily, with the default new selection. It creates/replaces the current date and never cleans up yesterday’s posts. Human reruns leave batch_target=latest; choose today only to deliberately start the current date instead. Selection rules, overwrite policy, account checks, kill switch, latest recorded feed/up-to-three Stories scope and no-retry behavior are unchanged. keep_today remains the existing action name, but means keep from the selected batch, including a previous date. All other history rows remain authoritative. The wrapper freezes run_date/batch_date before research; the publisher reads that prepared row rather than recomputing the clock.

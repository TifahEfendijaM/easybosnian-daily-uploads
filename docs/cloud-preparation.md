# Cloud preparation

The existing Cloudflare Worker dispatches preparation.yml at 05:00 Europe/Sarajevo with mode=daily. One ubuntu-22.04 job restores a dedicated cloud-only managed ChatGPT credential, runs the official pinned Codex CLI 0.160.0, stages reviewed content privately without a history write, generates/renders private artwork with visual placement review, persists the refreshed credential and publishes those exact prepared cards immediately afterward, saving history only once a feed is confirmed. No paid OpenAI API or awake Mac. There is no reusable workflow, queue commit, package handoff or recovery mode.

The research child uses a stripped environment, workspace-write sandbox, live web search, seven-minute limit, private logs, structured ready/blocked output schema and a tracked-file Git diff check. Provider/admin/GitHub secrets stay with the trusted wrapper. It can write unreviewed drafts/private research under build only. Free-form model output and raw events never go into issues or uploaded artifacts. The wrapper requires an actual reviewed draft and validates independently before private staging.

verify checks infrastructure and the child's actual workspace probe. It cannot choose content, write history, call FLUX, render or publish. Preview saves content if absent and otherwise reuses the selected history row; it renders privately. Every daily selection prepares fresh copy, prompts and design choices, retaining theme/words only as selected, then updates the selected batch for latest or creates an independent batch for none. The trusted wrapper enforces exact pinned metadata, permits historical repeats of explicit custom/retained choices and researched manual spelling corrections, and checks ChatGPT-selected or different fallback terms against full history. Known provider IDs are saved separately for deliberate cleanup; they never bind the date to immutable content or suppress a run. After rendering, latest attempts best-effort cleanup of only its batch’s final Instagram feed/associated Stories and Facebook feed post; none skips cleanup; deletion errors do not block independent publishing, and Facebook Stories/backing photos are never deleted; TikTok reruns continue without checking or confirming manual deletion; old TikTok posts must be removed manually if desired. See manual-reruns.md.

Credential bootstrap/persistence retains the dedicated temporary auth directory and managed-subscription validation. The workflow's always-run persistence step saves refreshed CODEX_AUTH_JSON with the separate repository-restricted GH_SECRETS_TOKEN, even after preparation fails. Never copy a desktop session, expose a token or use stale auth as a paid fallback.

Use scripts/cloud_auth_setup.py login then save only if dedicated cloud authorization needs renewal. Existing configured credentials remain. The old cloud proof commit/read-back is removed because connection verification no longer needs repository content writes. Safe verification results are workflow artifacts.

DAILY_POSTING_ENABLED is checked before daily preparation and every actual live publisher. verify/preview remain available while disabled. Missing schedules generate no notification. Failures during a run still produce private GitHub issues and build/failure.txt; no Healthchecks or watchdog exists.

Content instructions live in docs/cloud-agent-task.md and docs/preparation-task.md. All learner-visible copy is Bosnian. Quiz photography must be relevant: a pictured object is allowed when identifying it is the task, while images must not solve a hidden fact or reveal a written answer/option letter. Znaš li? prioritizes useful situations, meaningful comparisons and verified interesting facts over routine grammar drills. Translation-template rejection is a deterministic backstop, not a general language detector; the GPT reviewer still checks every public string and scene.

New captions finish with a short, witty Bosnian invitation tied to the batch and 👉easybosnian.com on the final line. The reviewer checks relevance and quiz secrecy; the trusted wrapper enforces the final website line before saving newly prepared content. Existing history/preview content is not retroactively changed.

Four daily selections now include custom inputs. same_words retains theme/words and individual levels but regenerates copy/captions/prompts and reselects palette/layouts; custom regenerates text and captions from requested values even when blank fields reuse the selected batch. The trusted context carries these inputs without expanding the child environment or credential access. Every newly prepared draft must include reviewed quiz_format and the contextual website footer; existing saved previews remain unchanged. fit_check measures both feed and B Story treatments for every card before a history save, including ordinary and yes/no quizzes.

The shared target_cefr is snapshotted from data/preparation-settings.json at preparation time and passed only as structured context. Fresh-text drafts record that exact top-level bosnian_level; same_words retains individual word levels while rewriting copy. Per-word custom actions resolve to pinned metadata or null slots delegated to the research child. Individual word levels govern rewritten copy; retained levels remain, and changed themes delegate keep-today slots. Custom spelling correction comes first; a reviewed invalid/incompatible entered or kept seed can fall back to ChatGPT under docs/difficulty-policy.md. Corrections use their researched individual level, new alternatives use the shared level, and both must pass full validation within the same research execution. The child environment remains stripped.

Znaš li? may explain a useful difference between two words or a broader topic, rather than one word. Its heading describes the lesson and need not equal its internal selection seed. For custom Znaš li?, select entered and type a word, a comparison such as “peći / kuhati”, or a short Bosnian topic. The existing second entry stores that seed for selection/history; fresh comparison/topic metadata includes its principal taught lemmas as novelty terms. Retained seed metadata stays exact. ChatGPT-selected comparisons/topics must be new against full previous lesson text and metadata; entered/kept comparisons may repeat history. Every taught term must respect quiz-answer secrecy. New lessons stay source-reviewed, Bosnian-only and measured for both feed and Story fit.

Replacement cleanup selects only the latest recorded batch within the selected batch_id: the last Instagram feed post and up to three Stories recorded after it, and the last Facebook feed post. It leaves all other independent batches alone and never fills a partial latest Story batch with older Story IDs. D1 insertion order is exposed as recorded_order in the authenticated ID listing; provider ID sorting is not used as a clock. If order is unavailable, cleanup warns/skips and publishing remains independently gated. Facebook Stories/photos and TikTok posts stay manual. No content history, reservation, intent, retry or daily-claim state is added.


## Independent batches and dates

History has one row per batch_id, not per date. date remains the Sarajevo content date. The Worker assigns created_at when a reviewed batch is first saved and preserves it on replacement; created_order breaks timestamp ties. Latest means the newest complete saved batch by this creation order, without adding new unpublished previews, not the largest calendar date or latest edit. Metadata-only imports remain novelty history but cannot be a reuse source.

batch_target=latest keeps that batch_id and its original date, completely replaces only its content, invalidates only its artwork and attempts cleanup only of its recorded final feed/up-to-three associated Stories on supported platforms. Other independent batches, even on the same date, stay intact. After midnight this can still replace yesterday’s batch. If no complete batch exists, latest creates the first batch for the current date and performs no cleanup.

batch_target=none creates a new UUID batch for the current Sarajevo date without changing/deleting any previous batch or its posts. It may use the newest complete batch as the source for same_words/same_theme/custom keep_today, even when that source is yesterday. The automatic 05:00 Worker sends mode=daily, batch_target=none and the default new selection, so it always adds the morning’s current-date batch. The native form has exactly latest/none; today is accepted only as a deprecated Python compatibility alias for creating an independent batch, not exposed in the form or sent by the Worker.

Use context["batch"]["batch_id"] as package.batch_id and context["batch"]["date"] as package.date. The wrapper freezes identity/date/source before research, then validates them independently. Reuse pinned metadata exactly. Explicit entered/retained theme and word equivalents, including researched corrections of manual seeds, are intentionally exempt across all history. Only themes/words actually chosen by ChatGPT, including different fallback seeds, compare against every row, including other batches on the same date. Source review, fresh copy, quiz secrecy, measured fit, individual difficulty and caption footer remain mandatory. None preserves its source history; latest overwrites only its selected row. Research/check timestamps describe the actual review now, never the old content date.

Private backgrounds/cards/Stories and local result directories use batch_id; public URLs remain random with 14-day expiry. Publication identifiers are scoped to batch_id as well as their reporting date. Cleanup refuses IDs from another batch. Legacy date-only write/generation/publication routes refuse ambiguous dates rather than guessing; use explicit batch paths. Rendering/publication validates stored schema/editorial flags/secrecy/fit; full-history novelty is enforced at trusted preparation/save, with explicit reuse, rather than rejecting deliberately retained words afterward. No publication state, hash, queue, retry, watchdog or new authorization is added. verify stays read-only; latest preview reuses exact saved content, none preview prepares/renders a separate private batch without saving history. DAILY_POSTING_ENABLED gates every live run and delete, including none.


## Photo-assessed declarative visual contract

Read `docs/visual-style-contract.md`, `src/easybosnian/designs.py` and `hybrid.py` for the active contract. After FLUX photos exist, one read-only ChatGPT call may choose each card's approved design and palette ID, and each exact-copy block's role, approved style, x/y/width, target font_size and line_spacing. Optional max_lines and balanced/natural wrapping are constraints, never permission to truncate. Photo windows expose only approved y/height/contain-or-cover geometry. Category/title anchors, fonts, logo, colours and drawing primitives remain renderer-controlled. No replacement text, manual line breaks, code, CSS, font filenames, custom colours, opacity, borders, radius, shadows or filter definitions are accepted.

Hybrid body treatments are rounded, outlined, overlay_dark, overlay_light, side_rule, caption, bottom_sheet, split_panel, minimal_rule, double_frame, notebook_margin, top_ribbon and corner_brackets; editorial supplies the fourteenth body treatment, plain. All twelve panel treatments also support quiz answers with any independently selected approved badge shape; plain and caption remain body-only. These are materially different renderers. Caption is body-only and at most three lines; bottom_sheet requires width >=660 and y >=700. Editorial lesson/word cards require plain body above a cover-fit photo and italic_footer below. PRIMJER has its own strict enum: italic_photo (no shade), italic_photo_fade (trusted neutral contrast fade), italic_footer (unboxed editorial paper footer). All use bundled Lora Italic, never the body catalogue or an example box.

Body font targets are 32–48px, answers 32–46px and examples 28–40px. Line spacing is a multiplier of font size, 1.20–1.55; actual accented glyph bounds must also fit without collisions. Pillow loads Inter/Lora, measures Unicode-aware wrapping and final heights, preserves exact source copy/diacritics, and rejects unsupported combinations, bounds/header/logo collisions, overlapping blocks, excessive opaque panel coverage, unreadable contrast and truncation. Separate photo windows are protected from body/answer overlays; visual-naming quizzes require question → complete contained photo → choices. Recognising an important subject in a full-background photo remains the visual model's judgment; geometric checks cannot guarantee semantic object detection.

One approved palette is selected independently per card after inspecting its natural photo colours. It affects text/panels only, never FLUX scene colours. Stories retain treatment B and use their corresponding card's final palette, Inter explanations and unboxed Lora Italic footer. Their layout/fonts remain trusted renderer presets rather than a second model call. The preparation palette is a deterministic fallback. design_template is accepted only for legacy reading, ignored by rendering and omitted from fresh content.

Invalid/unavailable/uncertain proposals use the deterministic measured hybrid fallback with no additional visual-model or image-generation call. Invalid measured geometry/contrast falls back for that card, using the preparation palette; integrity failures remain fatal. If even the exact-copy safe fallback cannot fit/read, fail before publication. Store only approved final design/style/typography/geometry/palette metadata, never free-form model output. Versioned private prepared JPEGs are reused unchanged for publishing after credential persistence. Verify cannot render, preview remains private. No clock, Worker, schema, history, cleanup, publishing or retry changes are required.

Quiz composition: every answer has independent x/y/width, approved panel style and bounded typography. Ordinary choices may be staggered across left/right and upper/middle/lower regions, preserving A/B/C/D reading order and measured visibility/fit. Do not treat them as a single stack or mechanically stack them. Each answer may independently choose marker_style=circle, rounded_square, square or triangle. Coordinated styles/badges are a preference, not a hard rule; mixtures are allowed when the image looks better. All colours remain from the image's approved palette; never highlight an answer as correct. Visual-naming quizzes keep the complete photograph protected with all choices below. Badge shapes are trusted Pillow presets, not model drawing primitives. For neighbouring answers intended as a shared row, choose exactly the same y and coordinated font_size/line_spacing, avoiding tiny accidental offsets. Pillow uses a shared measured font cell for answer heights and baselines, including Bosnian accents and descenders; equal typography and line counts therefore align. Different line counts may require different heights. Deliberate staggered arrangements stay available with clear spacing and label reading order; do not automatically snap independently placed choices into a grid.

Ordinary lesson/word feed cards prefer the full photographic background with separately placed approved body and italic example treatments. Separate middle photo windows are a less-frequent alternative, mainly when long exact copy or important photo subjects make a readable/elegant overlay difficult. Visual-identification quiz photo protection remains unchanged. Stories use treatment B with a thin palette-accent rule above PRIMJER, which remains unboxed Lora Italic.

Full-background hybrid is the strong ordinary-card default. Choose its approved body treatments freely after comparing compatible treatments and plausible independent block placements; the routine model sheet contains only the original photo and exact feed crop, without any styled reference that could bias the choice. Middle windows remain an exceptional last resort when long exact copy cannot fit elegantly or readable overlays would obscure important subjects. This is a content/photo-based preference, not a random selection probability.

The visual reviewer receives only the complete generated photographs and exact feed crops, without any rendered hybrid/editorial style example. Exact public block text and measured heights are supplied as data; quiz answer keys remain excluded. The deterministic default_plan is explicitly an uncertainty fallback, not an example to imitate. The approved catalogue, strict declarative choices, full-photo preference and measured safe fallback remain unchanged.

FLUX failures report a fixed stage/reason and, when available, a documented numeric Cloudflare AI error code. Cache read/write failures and a missing AI binding are distinguished from model failures. No raw provider text, prompts or credentials are logged, and no generation retry is added.

FLUX chooses the photograph’s composition. This overrides the original master prompt’s pre-image layout and text-space framing instructions. Write only the relevant scene, subjects/actions, environment, photographic realism, natural light, realistic textures and true-to-life colours. Do not direct subject position, camera framing, negative space, headroom, empty areas or a top/middle/bottom composition for overlays. Do not use measured copy or a guessed text position to shape the photograph. Leave composition to FLUX; the later visual reviewer adapts the approved text design and placement to the actual generated photo. Preserve quiz relevance and task-specific secrecy. Never request panels, coordinates, text, logos or recolouring to fit a palette.

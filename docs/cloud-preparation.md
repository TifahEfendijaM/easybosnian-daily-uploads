# Cloud preparation

The existing Cloudflare Worker dispatches preparation.yml at 05:00 Europe/Sarajevo with mode=daily. One ubuntu-22.04 job restores a dedicated cloud-only managed ChatGPT credential, runs the official pinned Codex CLI 0.160.0, saves reviewed content in D1, generates/renders private artwork with visual placement review, persists the refreshed credential and publishes those exact prepared cards immediately afterward. No paid OpenAI API or awake Mac. There is no reusable workflow, queue commit, package handoff or recovery mode.

The research child uses a stripped environment, workspace-write sandbox, live web search, seven-minute limit, private logs, structured ready/blocked output schema and a tracked-file Git diff check. Provider/admin/GitHub secrets stay with the trusted wrapper. It can write unreviewed drafts/private research under build only. Free-form model output and raw events never go into issues or uploaded artifacts. The wrapper requires an actual reviewed draft and validates independently before saving history.

verify checks infrastructure and the child's actual workspace probe. It cannot choose content, write history, call FLUX, render or publish. Preview saves content if absent and otherwise reuses the selected history row; it renders privately. Every daily selection prepares fresh copy, prompts and design choices, retaining theme/words only as selected, then updates the selected batch for latest or creates an independent batch for none. The trusted wrapper enforces exact pinned metadata, permits historical repeats of explicit custom/retained choices and researched manual spelling corrections, and checks ChatGPT-selected or different fallback terms against full history. Known provider IDs are saved separately for deliberate cleanup; they never bind the date to immutable content or suppress a run. After rendering, latest attempts best-effort cleanup of only its batch’s final Instagram feed/associated Stories and Facebook feed post; none skips cleanup; deletion errors do not block independent publishing, and Facebook Stories/backing photos are never deleted; TikTok reruns continue without checking or confirming manual deletion; old TikTok posts must be removed manually if desired. See manual-reruns.md.

Credential bootstrap/persistence retains the dedicated temporary auth directory and managed-subscription validation. The workflow's always-run persistence step saves refreshed CODEX_AUTH_JSON with the separate repository-restricted GH_SECRETS_TOKEN, even after preparation fails. Never copy a desktop session, expose a token or use stale auth as a paid fallback.

Use scripts/cloud_auth_setup.py login then save only if dedicated cloud authorization needs renewal. Existing configured credentials remain. The old cloud proof commit/read-back is removed because connection verification no longer needs repository content writes. Safe verification results are workflow artifacts.

DAILY_POSTING_ENABLED is checked before daily preparation and every actual live publisher. verify/preview remain available while disabled. Missing schedules generate no notification. Failures during a run still produce private GitHub issues and build/failure.txt; no Healthchecks or watchdog exists.

Content instructions live in docs/cloud-agent-task.md and docs/preparation-task.md. All learner-visible copy is Bosnian. Quiz photography must be relevant: a pictured object is allowed when identifying it is the task, while images must not solve a hidden fact or reveal a written answer/option letter. Znaš li? prioritizes useful situations, meaningful comparisons and verified interesting facts over routine grammar drills. Translation-template rejection is a deterministic backstop, not a general language detector; the GPT reviewer still checks every public string and scene.

New captions finish with a short, witty Bosnian invitation tied to the batch and 👉easybosnian.com on the final line. The reviewer checks relevance and quiz secrecy; the trusted wrapper enforces the final website line before saving newly prepared content. Existing history/preview content is not retroactively changed.

Four daily selections now include custom inputs. same_words retains theme/words and individual levels but regenerates copy/captions/prompts and reselects palette/layouts; custom regenerates text and captions from requested values even when blank fields reuse the selected batch. The trusted context carries these inputs without expanding the child environment or credential access. Every newly prepared draft must include reviewed quiz_format and the contextual website footer; existing saved previews remain unchanged. fit_check measures both feed and B Story treatments for every card before a history save, including ordinary and yes/no quizzes.

The shared target_cefr is snapshotted from data/preparation-settings.json at preparation time and passed only as structured context. Fresh-text drafts record that exact top-level bosnian_level; same_words retains individual word levels while rewriting copy. Per-word custom actions resolve to pinned metadata or null slots delegated to the research child. Individual word levels govern rewritten copy; retained levels remain, and changed themes delegate keep-today slots. Custom spelling correction comes first; a reviewed invalid/incompatible entered or kept seed can fall back to ChatGPT under docs/difficulty-policy.md. Corrections use their researched individual level, new alternatives use the shared level, and both must pass full validation within the same research execution. The child environment remains stripped.

Znaš li? may explain a useful difference between two words or a broader topic, rather than one word. Its heading describes the lesson and need not equal its internal selection seed. For custom Znaš li?, select entered and type a word, a comparison such as “peći / kuhati”, or a short Bosnian topic. The existing second entry stores that seed for selection/history; fresh comparison/topic metadata includes its principal taught lemmas as novelty terms. Retained seed metadata stays exact. ChatGPT-selected comparisons/topics must be new against full previous lesson text and metadata; entered/kept comparisons may repeat history. Every taught term must respect quiz-answer secrecy. New lessons stay source-reviewed, Bosnian-only and measured for both feed and Story fit.

Replacement cleanup selects only the latest recorded batch within the selected batch_id: the last Instagram feed post and up to three Stories recorded after it, and the last Facebook feed post. It leaves all other independent batches alone and never fills a partial latest Story batch with older Story IDs. D1 insertion order is exposed as recorded_order in the authenticated ID listing; provider ID sorting is not used as a clock. If order is unavailable, cleanup warns/skips and publishing remains independently gated. Facebook Stories/photos and TikTok posts stay manual. No content history, reservation, intent, retry or daily-claim state is added.


## Independent batches and dates

History has one row per batch_id, not per date. date remains the Sarajevo content date. The Worker assigns created_at when a reviewed batch is first saved and preserves it on replacement; created_order breaks timestamp ties. Latest means the newest complete saved batch by this creation order, including unpublished previews, not the largest calendar date or latest edit. Metadata-only imports remain novelty history but cannot be a reuse source.

batch_target=latest keeps that batch_id and its original date, completely replaces only its content, invalidates only its artwork and attempts cleanup only of its recorded final feed/up-to-three associated Stories on supported platforms. Other independent batches, even on the same date, stay intact. After midnight this can still replace yesterday’s batch. If no complete batch exists, latest creates the first batch for the current date and performs no cleanup.

batch_target=none creates a new UUID batch for the current Sarajevo date without changing/deleting any previous batch or its posts. It may use the newest complete batch as the source for same_words/same_theme/custom keep_today, even when that source is yesterday. The automatic 05:00 Worker sends mode=daily, batch_target=none and the default new selection, so it always adds the morning’s current-date batch. The native form has exactly latest/none; today is accepted only as a deprecated Python compatibility alias for creating an independent batch, not exposed in the form or sent by the Worker.

Use context["batch"]["batch_id"] as package.batch_id and context["batch"]["date"] as package.date. The wrapper freezes identity/date/source before research, then validates them independently. Reuse pinned metadata exactly. Explicit entered/retained theme and word equivalents, including researched corrections of manual seeds, are intentionally exempt across all history. Only themes/words actually chosen by ChatGPT, including different fallback seeds, compare against every row, including other batches on the same date. Source review, fresh copy, quiz secrecy, measured fit, individual difficulty and caption footer remain mandatory. None preserves its source history; latest overwrites only its selected row. Research/check timestamps describe the actual review now, never the old content date.

Private backgrounds/cards/Stories and local result directories use batch_id; public URLs remain random with 14-day expiry. Publication identifiers are scoped to batch_id as well as their reporting date. Cleanup refuses IDs from another batch. Legacy date-only write/generation/publication routes refuse ambiguous dates rather than guessing; use explicit batch paths. Rendering/publication validates stored schema/editorial flags/secrecy/fit; full-history novelty is enforced at trusted preparation/save, with explicit reuse, rather than rejecting deliberately retained words afterward. No publication state, hash, queue, retry, watchdog or new authorization is added. verify stays read-only; latest preview reuses exact saved content, none preview prepares/saves a separate private batch. DAILY_POSTING_ENABLED gates every live run and delete, including none.


## Photo-assessed Pillow design and placement

After the three real FLUX photographs exist, one read-only cloud ChatGPT call assesses them. It chooses one shared approved palette, a real supported Pillow design per card, and free x/y/width coordinates for each reviewed block. It does not invent drawing code, fonts, colours or text. Category/title anchors stay fixed; the chosen design controls their trusted appearance. Lora SemiBold headings, Inter explanations and Lora Italic examples use bundled licensed fonts. Final design IDs, per-block styles, placement and actual palette are captured in image-placement-result.json and the successful-run report; initial content palette/eight-layout fields remain scene-planning metadata. Stories use the final shared palette.

The approved catalogue lives in src/easybosnian/designs.py and is rendered by hybrid.py:

- **hybrid**: photographic background, rounded accent category badge and serif title. ChatGPT chooses rounded or outlined explanation/answer panels. PRIMJER can be pure italic text over a calm photograph (italic_photo), without a card, or a readable boxed example. Prefer a wide calm photo footer for examples like Pluralizam/Identitet, while keeping subjects visible; this is guidance rather than forced placement.
- **editorial**: lesson/word paper page with a tracked category label/underline, serif title, plain explanation above a large wide photograph, and an unboxed italic example below it with a separator (italic_footer). This supports the preferred larger-photo Izlaznost design. The photo uses an explicitly selected centered cover crop; ChatGPT must assess whether faces/actions survive that crop. If they do not, use hybrid/full-photo or contain instead. Body and footer never overlap the separate photograph.

Hybrid may also contain a complete separate photograph without cropping/stretching: its panels stay outside the actual contained image and an italic_photo example stays inside with 20px inset. Full-background cards keep their ordinary feed crop. Visual-identification quizzes retain question → complete photo → answers, and all treatment-B Stories retain their established separate-photo geometry and Inter panels. Ordinary quiz choices can be independently placed while preserving A/B/C/D reading order; clear choice cards remain compulsory.

The visual child receives original/feed-crop/reference pictures (including an editorial reference when measured copy fits), public headings/prompts and per-style measured text heights. Its stripped environment, read-only sandbox, disabled search, strict enum/coordinate contract and tracked-file integrity check remain. Pillow independently rejects unsupported style combinations, lost/reordered blocks, header/logo collisions, overlapping text/photo sections, excessive panel coverage, clipping and unreadable contrast. Body sizing remains 44/38/34 px, with exact copy/diacritics and no truncation. Only the editorial footer can extend below y1170, ending by y1286 and left of x880 so it cannot hit the fixed logo. Photo text gets minimal neutral contrast protection, never a palette colour wash. Subject recognition remains a visual judgment rather than a guarantee.

Invalid/unavailable/uncertain proposals use the measured rounded-panel hybrid reference without another model call or FLUX generation. Integrity failures remain fatal. Publishing reuses the exact private prepared JPEGs and versioned manifest after dedicated cloud-credential persistence; it does not rerender. Verify cannot render, preview stays private. No clock, batch/history/cleanup, kill switch, provider credential, retry or Story-geometry change is introduced. No Worker/schema migration or deployment is required; merging the checked repository change activates it for subsequent runs.

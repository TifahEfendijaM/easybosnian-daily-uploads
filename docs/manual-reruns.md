# Deliberate same-day replacement

Open [this workflow](https://github.com/TifahEfendijaM/easybosnian-daily-uploads/actions/workflows/preparation.yml) → **Run workflow**. Keep branch **main**, select mode **daily**, choose a content_selection below, and confirm TikTok deletion when applicable. Click the green **Run workflow** once and follow the newly created run. Use this form to choose different inputs; the old run's **Re-run jobs** button retains that run's original inputs.

For a same-day replacement, first delete the current post in @easy.bosnian, then tick **I manually deleted today's previous TikTok post before this daily rerun** (tiktok_previous_removed). Instagram and Facebook clean up their known same-date content themselves. A new date with no previous TikTok post needs no acknowledgement.

Selections:

| content_selection | Result |
|---|---|
| new (default) | New theme and three new words, compared with all current history |
| same_theme | Keep today's exact theme metadata; choose three different words |
| same_words | Keep the complete saved content, caption, palette and layouts; generate new background prompts/images only |
| custom | Use the entered theme/three words, with fresh text, caption and background prompts; blank/default keeps today's latest value; an explicit word action can delegate selection to ChatGPT |

Reuse requires today's complete content row. Old metadata-only imports cannot be rendered or used as a reuse source. Fresh-text choices review sources and Bosnian correctness again. Image-only reuse preserves already-reviewed content and reviews new scene relevance/secrecy. Every choice validates schema and measured feed/Story fit. Only explicitly reused same-date metadata is exempt from novelty checks; older rows remain authoritative. Preview still reuses today's row without publishing or deleting. Verify only checks connections/workspace. The scheduled Worker sends mode=daily and receives the default new selection; no dispatch API or cron-claim changes are needed.

Preparation saves today's replacement row and invalidates cached artwork. After fresh cards render successfully, cleanup checks only that date's stored provider IDs on the verified publishing account. It lists owned media completely before treating a missing ID as manually deleted/expired. Permission, pagination or network errors stop that platform; they never count as already deleted. Known old Instagram carousels and image Stories, Facebook feed posts, photo Stories and uploaded photos are removed before that platform posts replacement content. The global publishing switch also gates deletion. Disabled platforms are not cleaned. Other enabled platforms continue independently after a failure.

There is a small private publication_ids table with date/platform/kind/object_id/account_id only. IDs are written immediately after a provider returns them, before read-back, including partial results. Deleted/confirmed absent IDs are removed. It is not a publication state machine: no intents, hashes, revisions, immutable packages, retries or completion gate. A request that times out without returning an ID may still have published and cannot be located automatically. Likewise, an accepted Buffer submission remains a known ID even while upstream publication is pending. Inspect uncertain outcomes manually.

**TikTok:** Buffer cannot delete an already-published TikTok post. Delete today's old post in TikTok yourself, then tick **tiktok_previous_removed** for the rerun. Without acknowledgement, TikTok replacement fails explicitly; Instagram and Facebook can still proceed. A first upload needs no acknowledgement. This acknowledgement does not call Buffer deletePost or claim API deletion.

**Facebook:** Existing Page token permissions pages_manage_posts, pages_read_engagement and pages_show_list are retained. No new Facebook publishing/deletion consent or token is introduced. Meta's Page post/photo deletion endpoints return success. A Facebook Story node itself has no supported DELETE operation: cleanup maps the owned Story to its same-date recorded photo, verifies the photo's owner, page_story_id and can_delete, deletes that photo once and requires the Story to disappear from the complete Page Stories edge. It never substitutes a guessed feed-post ID or treats a permission error as absence. No deletion request is retried.

**Instagram:** Deletion uses the distinct Instagram API with Facebook Login, instagram_basic and instagram_manage_contents, through Page 1284422991426579 and verified @easy_bosnian. It requires that Page and professional Instagram profile to be formally linked. Save **INSTAGRAM_DELETE_ACCESS_TOKEN** (long-lived Facebook User token) and **INSTAGRAM_DELETE_USER_ID** (Facebook Login's Instagram ID) privately. The existing Instagram Login publishing/refresh credentials remain untouched. Authorize with `easybosnian authorize-instagram-deletion` using hidden prompts. Meta's Facebook User token has a finite lifetime; reauthorize before the expiry in docs/instagram-deletion-authorization.json when deletion is needed. There is no unattended Facebook User-token refresh added. An expired/missing deletion token affects same-date Instagram replacement, not a first new-date publication. Instagram Login and Facebook Login may use different IDs for the same profile: cleanup accepts only the configured publishing ID or the separately verified linked deletion ID, then checks ownership through that exact profile.

# Layout selection

The user's original eight card treatments are retained. They primarily place text in the upper portion and vary panels, category styling and spacing. Preparation selects a layout independently per card and matches a short, natural photorealistic composition to its actual text extent. No layout IDs, coordinates, blank regions or text-placement instructions are sent to FLUX. Dynamic body fonts remain 44/38/34 px at 160/240 character boundaries, with measured fit, contrast and unchanged Bosnian diacritics. Separate PRIMJER label and inset accent remain. The proposed wider positional redesign was rejected and is not deployed.

# Deploying selection/presentation changes

Review the full branch diff and actual card previews, run Python/Worker tests, then merge into main. No Worker payload, cron or D1 migration changes are required: its existing mode=daily dispatch receives the default new selection. Main checks verify the deployed infrastructure without publishing. # Let another person launch runs

This is a private repository owned by a personal account. In repository **Settings → Collaborators → Add people**, invite the person's exact GitHub username. After accepting, that collaborator has write access and can use the same workflow link and form. Sharing the link alone grants no access. Personal private repositories do not offer an Actions-only collaborator role; collaborator access also permits editing repository code. No social token needs to be shared separately.

Official references: [manual workflow runs](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow), [inviting collaborators](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/repository-access-and-collaboration/inviting-collaborators-to-a-personal-repository), [personal-repository permission levels](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/repository-access-and-collaboration/permission-levels-for-a-personal-account-repository).

Facebook API references: [Story node operations](https://developers.facebook.com/docs/graph-api/reference/stories/), [Photo deletion](https://developers.facebook.com/docs/graph-api/reference/photo/#Deleting), [Story media identifiers](https://developers.facebook.com/documentation/video-api/page-stories-api). The live provider uses lowercase published even though the guide shows uppercase; publication checks normalize case without weakening identity checks.

# Custom fields and current presentation

For custom only, enter custom_theme and choose each custom_word_N_action in quiz/lesson/word order: keep_today (empty field retains today’s latest word), chatgpt (empty field lets ChatGPT select a new word), or entered (fill the matching custom_word_N field). Blank fields resolve from today's current saved row at the start of preparation; GitHub cannot dynamically display those values as form defaults. Leaving all blank deliberately regenerates the same theme/words with fresh instructional copy and captions. If no saved row exists, enter a theme and enter or delegate every word. Manual inputs do not bypass research, standard Bosnian or older-history novelty checks. Each replacement overwrites today's active history completely, as before. Keep mode=daily; verify never prepares/publishes and preview reuses today's saved content.

same_words now means images only. It preserves captions and every other content field, including older captions without the website footer, palette, templates and quiz format. Use custom with blank fields when you want fresh text for the same theme/words. This intentional change replaces the earlier same_words meaning. Routine 05:00 Cloudflare dispatches still use new.

Stories use B for word/lesson cards and visual naming quizzes, A for other quizzes. Regular word/lesson posts stay unchanged. Only explicitly reviewed visual_identification quizzes use B on the regular quiz slide too; other quiz types retain the normal overlay. Photos are fully fitted, copy is never truncated and no extra FLUX generation occurs.

# Change the shared difficulty

Open [Change EasyBosnian difficulty](https://github.com/TifahEfendijaM/easybosnian-daily-uploads/actions/workflows/configure-level.yml), choose Run workflow on main, select A1/A2/B1/B2/C1/C2 and run once. Initially it is A2. Wait for that settings run to succeed before starting a rerun. The setting persists in data/preparation-settings.json and applies to future automatic/manual preparation until changed again; it does not alter a run already underway. This separate configuration workflow does not prepare, render or publish anything, and is the only workflow with contents-write permission. The publication pipeline remains one job with verify/preview/daily.

same_words preserves its existing copy/level exactly. New ChatGPT-selected words and their instructional copy use the shared level. Retained words keep their previous individual difficulty when rewritten. Compatible entered words keep their own reviewed difficulty; the shared level does not force replacing them. Saved preview content is not rewritten. Each new history package records bosnian_level. GitHub displays all custom controls because the standard dispatch form cannot conditionally hide them; they are ignored outside custom. Keep a word field empty for keep_today/chatgpt, or select entered and supply its word. Blank custom fields refer to today’s latest saved batch, not a retained original 05:00 snapshot.

Custom theme changes convert keep_today slots into new ChatGPT choices at the shared level. A compatible entered word remains; an incompatible entered word is replaced automatically with a suitable word at that level, documented in private review. This thematic replacement never bypasses older-history novelty checks. Top-level bosnian_level records the settings snapshot, while words carry individual levels; legacy retained words without a known level keep their existing style. See difficulty-policy.md. Visual quizzes put the question above the complete photograph, then choices below it, in both posts and Stories.

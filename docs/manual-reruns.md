# Manual batches and replacement

Open [this workflow](https://github.com/TifahEfendijaM/easybosnian-daily-uploads/actions/workflows/preparation.yml) → **Run workflow**. Keep branch **main**, select mode **daily**, leave batch_target at **latest**, choose a content_selection below, and leave custom controls untouched unless you choose custom. Click the green **Run workflow** once and follow the newly created run. Use this form to choose different inputs; the old run's **Re-run jobs** button retains that run's original inputs.

Instagram attempts batch-specific feed/Story cleanup and Facebook attempts feed cleanup, but deletion failures do not block replacement publishing. Facebook Stories stay manual. TikTok’s earlier post can only be removed manually; delete it yourself if you want only the new version. There is no TikTok confirmation checkbox or API deletion check, and leaving the earlier post present does not block a rerun.

Selections:

| content_selection | Result |
|---|---|
| new (default) | New theme and three new words, compared with all current history |
| same_theme | Keep the selected batch's exact theme metadata; choose three different words |
| same_words | Keep theme/three words; regenerate all text, caption, prompts/images and palette/layout choices |
| custom | Use the entered theme/three words, with fresh text, caption and background prompts; blank/default keeps the selected batch's value; an explicit word action can delegate selection to ChatGPT |

Reuse requires a complete saved source; all_today prefers the latest complete batch from today, otherwise the latest complete older row. Old metadata-only imports cannot be rendered or used as a reuse source. Fresh-text choices review sources and Bosnian correctness again. same_words researches fresh claims and scenes and reselects palette/layouts, retaining each word’s previous difficulty. Every choice validates schema and measured feed/Story fit. Explicit retained metadata is exempt across saved copies; newly selected terms compare against every saved batch. Preview reuses the selected saved row without publishing or deleting. Verify only checks connections/workspace. The scheduled Worker sends mode=daily and batch_target=none with the default new selection; cron claims and timing are unchanged.

Preparation saves the selected replacement row under its original date and invalidates cached artwork. After fresh cards render successfully, latest cleanup checks only that selected batch's stored IDs on the verified account. Instagram attempts owned feed/Story deletion; Facebook attempts owned feed-post deletion only. An authenticated complete edge is required before treating a missing ID as already absent. Errors stop that cleanup attempt and preserve uncertain IDs, but the independently verified replacement publisher still runs. No deletion is retried. The global switch still gates every delete and publish; disabled platforms are not cleaned. Cleanup or all_today history-removal failure is recorded in the private platform result, run summary and failure issue with the new publication outcome. A successful replacement can therefore have a cleanup warning and leave earlier content present.

**TikTok:** Buffer cannot delete an already-published TikTok post or verify your manual removal through this workflow. Reruns proceed after the usual channel/kill-switch checks without a deletion acknowledgement. Previous known IDs remain recorded, and the result reports that deletion was not checked/performed. Remove earlier posts yourself if you want only the newest version.

**Facebook:** Retain the existing separate Page token and permissions. Feed-post deletion is supported and remains best effort. [Meta's Page Stories guide](https://developers.facebook.com/documentation/video-api/page-stories-api) documents publishing and reading, without a supported Story deletion operation. Do not try to delete Story nodes or their backing photos. The previously attempted photo workaround was rejected on October 3 despite can_delete=true; neither that flag nor code 10 proves the mechanism behind the refusal. Existing recorded photo IDs mix feed and Story uploads, so standalone photo cleanup is also skipped to protect Story media. Feed post deletion may leave uploaded photos present; this is an explicit consequence of removing the workaround, and their IDs remain recorded. Remove old Stories/photos manually if desired. Leaving them present does not block new feed or Story publication.

Instagram image Stories require two consecutive FINISHED container reads five seconds apart before their single publish request. This mitigates a readiness propagation race; it does not guarantee Meta will accept publication. PUBLISHED, ERROR and EXPIRED containers are never republished. A failed Story artifact retains container IDs, readiness and read-only post-failure status alongside known published Story IDs. No publish request is retried. Provider failures expose numeric code/subcode or success=false, never raw provider messages or credentials. Verify mode also reads today's recorded Meta object capabilities and writes a private meta-diagnostics-result.json; it never deletes or publishes.

**Instagram:** Deletion uses the distinct Instagram API with Facebook Login, instagram_basic and instagram_manage_contents, through Page 1284422991426579 and verified @easy_bosnian. It requires that Page and professional Instagram profile to be formally linked. Save **INSTAGRAM_DELETE_ACCESS_TOKEN** (long-lived Facebook User token) and **INSTAGRAM_DELETE_USER_ID** (Facebook Login's Instagram ID) privately. The existing Instagram Login publishing/refresh credentials remain untouched. Authorize with `easybosnian authorize-instagram-deletion` using hidden prompts. Meta's Facebook User token has a finite lifetime; reauthorize before the expiry in docs/instagram-deletion-authorization.json when deletion is needed. There is no unattended Facebook User-token refresh added. An expired/missing deletion token prevents that cleanup attempt but does not block publishing; old content may remain. Instagram Login and Facebook Login may use different IDs for the same profile: cleanup accepts only the configured publishing ID or the separately verified linked deletion ID, then checks ownership through that exact profile.

## Independent batches and dates

History has one row per batch_id, not per date. date remains the Sarajevo content date. The Worker assigns created_at when a reviewed batch is first saved and preserves it on replacement; created_order breaks timestamp ties. Latest means the newest complete saved batch by this creation order, without adding new unpublished previews, not the largest calendar date or latest edit. Metadata-only imports remain novelty history but cannot be a reuse source.

batch_target=latest keeps that batch_id and its original date, completely replaces only its content, invalidates only its artwork and attempts cleanup only of its recorded final feed/up-to-three associated Stories on supported platforms. Other independent batches, even on the same date, stay intact. After midnight this can still replace yesterday’s batch. If no complete batch exists, latest creates the first batch for the current date and performs no cleanup.

batch_target=none creates a new UUID batch for the current Sarajevo date without changing/deleting any previous batch or its posts. It may use the newest complete batch as the source for same_words/same_theme/custom keep_today, even when that source is yesterday. The automatic 05:00 Worker sends mode=daily, batch_target=none and the default new selection, so it always adds the morning’s current-date batch. The native form has exactly latest/none/all_today; today is accepted only as a deprecated Python compatibility alias for creating an independent batch, not exposed in the form or sent by the Worker.

Use context["batch"]["batch_id"] as package.batch_id and context["batch"]["date"] as package.date. The wrapper freezes identity/date/source before research, then validates them independently. Reuse pinned metadata exactly. Explicit entered/retained theme and word equivalents, including researched corrections of manual seeds, are intentionally exempt across all history. Only themes/words actually chosen by ChatGPT, including different fallback seeds, compare against every row, including other batches on the same date. Source review, fresh copy, quiz secrecy, measured fit, individual difficulty and caption footer remain mandatory. None preserves its source history; latest overwrites only its selected row. Research/check timestamps describe the actual review now, never the old content date.

Private backgrounds/cards/Stories and local result directories use batch_id; public URLs remain random with 14-day expiry. Publication identifiers are scoped to batch_id as well as their reporting date. Cleanup refuses IDs from another batch. Legacy date-only write/generation/publication routes refuse ambiguous dates rather than guessing; use explicit batch paths. Rendering/publication validates stored schema/editorial flags/secrecy/fit; full-history novelty is enforced at trusted preparation/save, with explicit reuse, rather than rejecting deliberately retained words afterward. No publication state, hash, queue, retry, watchdog or new authorization is added. verify stays read-only; latest preview reuses exact saved content, none/all_today preview prepares/renders a separate private batch without history writes or cleanup. DAILY_POSTING_ENABLED gates every live run and delete, including none and all_today.


Every newly prepared caption weaves the actual lesson difficulty into a natural Bosnian sentence connected to the theme, instead of a standalone label. Use caption_levels(package): when all three individual word/lesson levels are known, mention their frozen run target or only the lowest/highest endpoints for a mixed lesson (for example “Kroz svakodnevne situacije danas vježbamo bosanski na nivou B2.” or “Današnji primjeri povezuju gradivo od nivoa A1 do B2.”). Do not relabel retained lower-level copy with a newer global setting. If any retained legacy level is unknown, preserve that null rating and address the configured target audience naturally instead (for example “Učite bosanski na nivou B2? ...”), without claiming an official rating for those words. Vary the sentence to fit this batch; never copy these examples mechanically. Review the wording and level/range privately, keep all prose Bosnian, preserve quiz-answer secrecy and the caption limit, and leave 👉easybosnian.com on the final line. Fresh preparation/save requires require_caption_level=True; existing saved previews are not rewritten merely to add a level.

batch_target=all_today creates a new UUID batch for the frozen current Sarajevo date. Before research, the trusted wrapper freezes every earlier same-date history batch and every batch with known publication IDs for that date, including IDs whose history was previously erased. It prefers the latest complete same-date row for reuse; if today is empty, it may use the latest complete older row as a source just like none, but never targets that older row for cleanup. All history remains available for novelty/review during preparation and rendering. After rendering, daily attempts the frozen known Instagram feed/Story and Facebook feed cleanup IDs before independent publishing. Only after a feed is confirmed and its new history row is saved does daily remove the frozen earlier same-date history rows and their private artwork, allowing their themes/words to be selected on future runs. If no feed is confirmed or saving fails, earlier history stays intact. It preserves the new row, other dates, and unsupported/uncertain publication IDs; those IDs carry no content novelty and are retained only for ownership-scoped cleanup. Facebook Stories/photos and TikTok remain manual; disabled platforms are not cleaned. Cleanup/history-removal failures warn but do not block independently gated posting. Public random image URLs retain their original 14-day expiry. Empty today behaves like none with no fallback deletion of yesterday. Preview only stages/renders a new private batch without saving history and never removes history or social content; verify remains read-only. No new table, migration, retry, state machine or clock change is needed.

## Confirming Instagram cleanup

Instagram cleanup checks the complete authenticated media listing once after each accepted DELETE. A surviving ID or failed read produces a cleanup warning and keeps that ID; it never repeats the DELETE, and replacement publishing continues independently. Only confirmed absence is counted as removed and forgotten. This is a read within the current attempt, without publication state, retries or a new schedule.


Language policy for fresh content: lesson/word definitions and explanations (card.body) and quiz questions are in natural English when that individual word/lesson is rated A1 or A2; B1–C2 explanations/questions stay standard Bosnian. Set each non-quiz card.body_language and the quiz card.question_language to en/bs according to its own assigned word level. Set private_review.language_policy_checked=true only after actually reviewing English accuracy, the language of every question/explanation and the Bosnian portions. Quiz answer choices always remain Bosnian, including Da/Ne; words, headings, examples, captions, hashtags and alt text also remain Bosnian. An A1/A2 quiz may ask an English description such as “Which word means the male parent?” with Bosnian options; never put the correct Bosnian answer or an option letter in the question. Keep the same exact reviewed question/options in feed, Story and native-poll caption handling; no renderer translation. Unknown legacy individual levels stay Bosnian rather than inventing a rating. Preserve exact Bosnian examples and diacritics. Do not replace the Bosnian featured word/title or option strings with English translations; an English body may naturally define their meaning, and never leak the quiz answer or identifying hints through an English explanation. Do not ask for translation of a foreign word in the quiz. Use descriptions, situations or visual naming in the question language required by the quiz word’s individual level. Internal FLUX prompts and research/equivalence metadata may remain English. Existing saved previews are read unchanged; only newly researched copy follows this policy.

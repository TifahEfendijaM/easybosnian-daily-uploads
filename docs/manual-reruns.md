# Deliberate same-day replacement

Open [this workflow](https://github.com/TifahEfendijaM/easybosnian-daily-uploads/actions/workflows/preparation.yml) → **Run workflow**. Keep branch **main**, select mode **daily**, choose a content_selection below, and leave custom controls untouched unless you choose custom. Click the green **Run workflow** once and follow the newly created run. Use this form to choose different inputs; the old run's **Re-run jobs** button retains that run's original inputs.

Instagram attempts same-date feed/Story cleanup and Facebook attempts feed cleanup, but deletion failures do not block replacement publishing. Facebook Stories stay manual. TikTok’s earlier post can only be removed manually; delete it yourself if you want only the new version. There is no TikTok confirmation checkbox or API deletion check, and leaving the earlier post present does not block a rerun.

Selections:

| content_selection | Result |
|---|---|
| new (default) | New theme and three new words, compared with all current history |
| same_theme | Keep today's exact theme metadata; choose three different words |
| same_words | Keep theme/three words; regenerate all text, caption, prompts/images and palette/layout choices |
| custom | Use the entered theme/three words, with fresh text, caption and background prompts; blank/default keeps today's latest value; an explicit word action can delegate selection to ChatGPT |

Reuse requires today's complete content row. Old metadata-only imports cannot be rendered or used as a reuse source. Fresh-text choices review sources and Bosnian correctness again. same_words researches fresh claims and scenes and reselects palette/layouts, retaining each word’s previous difficulty. Every choice validates schema and measured feed/Story fit. Only explicitly reused same-date metadata is exempt from novelty checks; older rows remain authoritative. Preview still reuses today's row without publishing or deleting. Verify only checks connections/workspace. The scheduled Worker sends mode=daily and receives the default new selection; no dispatch API or cron-claim changes are needed.

Preparation saves today's replacement row and invalidates cached artwork. After fresh cards render successfully, cleanup checks only that date's stored IDs on the verified account. Instagram attempts owned feed/Story deletion; Facebook attempts owned feed-post deletion only. An authenticated complete edge is required before treating a missing ID as already absent. Errors stop that cleanup attempt and preserve uncertain IDs, but the independently verified replacement publisher still runs. No deletion is retried. The global switch still gates every delete and publish; disabled platforms are not cleaned. Cleanup failure is recorded in the private platform result, run summary and failure issue with the new publication outcome. A successful replacement can therefore have a cleanup warning and leave earlier content present.

**TikTok:** Buffer cannot delete an already-published TikTok post or verify your manual removal through this workflow. Reruns proceed after the usual channel/kill-switch checks without a deletion acknowledgement. Previous known IDs remain recorded, and the result reports that deletion was not checked/performed. Remove earlier posts yourself if you want only the newest version.

**Facebook:** Retain the existing separate Page token and permissions. Feed-post deletion is supported and remains best effort. [Meta's Page Stories guide](https://developers.facebook.com/documentation/video-api/page-stories-api) documents publishing and reading, without a supported Story deletion operation. Do not try to delete Story nodes or their backing photos. The previously attempted photo workaround was rejected on October 3 despite can_delete=true; neither that flag nor code 10 proves the mechanism behind the refusal. Existing recorded photo IDs mix feed and Story uploads, so standalone photo cleanup is also skipped to protect Story media. Feed post deletion may leave uploaded photos present; this is an explicit consequence of removing the workaround, and their IDs remain recorded. Remove old Stories/photos manually if desired. Leaving them present does not block new feed or Story publication.

Instagram image Stories require two consecutive FINISHED container reads five seconds apart before their single publish request. This mitigates a readiness propagation race; it does not guarantee Meta will accept publication. PUBLISHED, ERROR and EXPIRED containers are never republished. A failed Story artifact retains container IDs, readiness and read-only post-failure status alongside known published Story IDs. No publish request is retried. Provider failures expose numeric code/subcode or success=false, never raw provider messages or credentials. Verify mode also reads today's recorded Meta object capabilities and writes a private meta-diagnostics-result.json; it never deletes or publishes.

**Instagram:** Deletion uses the distinct Instagram API with Facebook Login, instagram_basic and instagram_manage_contents, through Page 1284422991426579 and verified @easy_bosnian. It requires that Page and professional Instagram profile to be formally linked. Save **INSTAGRAM_DELETE_ACCESS_TOKEN** (long-lived Facebook User token) and **INSTAGRAM_DELETE_USER_ID** (Facebook Login's Instagram ID) privately. The existing Instagram Login publishing/refresh credentials remain untouched. Authorize with `easybosnian authorize-instagram-deletion` using hidden prompts. Meta's Facebook User token has a finite lifetime; reauthorize before the expiry in docs/instagram-deletion-authorization.json when deletion is needed. There is no unattended Facebook User-token refresh added. An expired/missing deletion token prevents that cleanup attempt but does not block publishing; old content may remain. Instagram Login and Facebook Login may use different IDs for the same profile: cleanup accepts only the configured publishing ID or the separately verified linked deletion ID, then checks ownership through that exact profile.

# Layout selection

The user's original eight card treatments are retained. They primarily place text in the upper portion and vary panels, category styling and spacing. Preparation selects a layout independently per card and matches a short, natural photorealistic composition to its actual text extent. No layout IDs, coordinates, blank regions or text-placement instructions are sent to FLUX. Dynamic body fonts remain 44/38/34 px at 160/240 character boundaries, with measured fit, contrast and unchanged Bosnian diacritics. Separate PRIMJER label and inset accent remain. The proposed wider positional redesign was rejected and is not deployed.

# Let another person launch runs

This is a private repository owned by a personal account. In repository **Settings → Collaborators → Add people**, invite the person's exact GitHub username. After accepting, that collaborator has write access and can use the same workflow link and form. Sharing the link alone grants no access. Personal private repositories do not offer an Actions-only collaborator role; collaborator access also permits editing repository code. No social token needs to be shared separately.

Official references: [manual workflow runs](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow), [inviting collaborators](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/repository-access-and-collaboration/inviting-collaborators-to-a-personal-repository), [personal-repository permission levels](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/repository-access-and-collaboration/permission-levels-for-a-personal-account-repository).

Facebook API references: [Feed-post deletion](https://developers.facebook.com/documentation/pages-api/posts), [Story publishing and reads](https://developers.facebook.com/documentation/video-api/page-stories-api). The live provider uses lowercase published even though the guide shows uppercase; publication checks normalize case without weakening identity checks.

# Custom fields and current presentation

For custom only, enter custom_theme and choose each custom_word_N_action in quiz/lesson/word order: keep_today (empty field retains today’s latest word), chatgpt (empty field lets ChatGPT select a new word), or entered (fill the matching custom_word_N field). Blank fields resolve from today's current saved row at the start of preparation; GitHub cannot dynamically display those values as form defaults. Leaving all blank deliberately regenerates the same theme/words with fresh instructional copy and captions. If no saved row exists, enter a theme and enter or delegate every word. Manual inputs do not bypass research, standard Bosnian or older-history novelty checks. Each replacement overwrites today's active history completely, as before. Keep mode=daily; verify never prepares/publishes and preview reuses today's saved content.

same_words regenerates all text, caption and images for today’s same theme and words, and selects the palette/per-card layouts again. It is no longer an image-only option. It meets all current content validation, website-footer and quiz-format requirements. Routine 05:00 Cloudflare dispatches still use new.

Stories use B for word/lesson cards and visual naming quizzes, A for other quizzes. Regular word/lesson posts stay unchanged. Only explicitly reviewed visual_identification quizzes use B on the regular quiz slide too; other quiz types retain the normal overlay. Photos are fully fitted, copy is never truncated and no extra FLUX generation occurs.

# Change the shared difficulty

Open [Change EasyBosnian difficulty](https://github.com/TifahEfendijaM/easybosnian-daily-uploads/actions/workflows/configure-level.yml), choose Run workflow on main, select A1/A2/B1/B2/C1/C2 and run once. Initially it is A2. Wait for that settings run to succeed before starting a rerun. The setting persists in data/preparation-settings.json and applies to future automatic/manual preparation until changed again; it does not alter a run already underway. This separate configuration workflow does not prepare, render or publish anything, and is the only workflow with contents-write permission. The publication pipeline remains one job with verify/preview/daily.

same_words rewrites copy and design while retaining individual word levels. New ChatGPT-selected words and their instructional copy use the shared level. Retained words keep their previous individual difficulty when rewritten. Compatible entered words keep their own reviewed difficulty; the shared level does not force replacing them. Saved preview content is not rewritten. Each new history package records bosnian_level. GitHub displays all custom controls because the standard dispatch form cannot conditionally hide them; they are ignored outside custom. Keep a word field empty for keep_today/chatgpt, or select entered and supply its word. Blank custom fields refer to today’s latest saved batch, not a retained original 05:00 snapshot.

Custom theme changes convert keep_today slots into new ChatGPT choices at the shared level. A compatible entered word remains; an incompatible entered word is replaced automatically with a suitable word at that level, documented in private review. This thematic replacement never bypasses older-history novelty checks. Top-level bosnian_level records the settings snapshot, while words carry individual levels; legacy retained words without a known level keep their existing style. See difficulty-policy.md. Visual quizzes put the question above the complete photograph, then choices below it, in both posts and Stories.

# Reading the GitHub form

Start with mode: daily prepares/publishes; preview renders without posting; verify checks connections only. content_selection controls the daily replacement. For same_words, same_theme or new, IGNORE every custom_theme/custom_word/action control; their defaults have no effect. Only custom uses those controls, independently for Pitanje dana, Znaš li? and Riječ dana. keep_today: leave its word field empty; chatgpt: leave it empty and let the agent choose; entered: type the word in the matching field. Blank theme retains today's latest saved theme. A changed theme delegates keep-today slots to the agent so the words fit it. Theme compatibility and per-word difficulty follow difficulty-policy.md.

The former TikTok deletion checkbox is removed. TikTok deletion remains manual and is never checked or claimed by this pipeline. Instagram feed/Stories and Facebook feed use best-effort known-ID cleanup; failed cleanup does not block posting, and Facebook Stories are manual. Shared difficulty lives in the separate Change EasyBosnian difficulty workflow, not in this form. GitHub shows custom controls for every selection; conditional field visibility is unavailable in this native workflow form.

Znaš li? may explain a useful difference between two words or a broader topic, rather than one word. Its heading describes the lesson and need not equal its internal selection seed. For custom Znaš li?, select entered and type a word, a comparison such as “peći / kuhati”, or a short Bosnian topic. The existing second entry stores that seed for selection/history; fresh comparison/topic metadata includes its principal taught lemmas as novelty terms. Retained seed metadata stays exact; the reviewer also checks full previous lesson text. Additional taught terms must respect history novelty and quiz-answer secrecy. New lessons stay source-reviewed, Bosnian-only and measured for both feed and Story fit.

Replacement cleanup selects only the latest recorded batch on the selected Sarajevo date: the last Instagram feed post and up to three Stories recorded after it, and the last Facebook feed post. It leaves earlier same-date batches alone and never fills a partial latest Story batch with older Story IDs. D1 insertion order is exposed as recorded_order in the authenticated ID listing; provider ID sorting is not used as a clock. If order is unavailable, cleanup warns/skips and publishing remains independently gated. Facebook Stories/photos and TikTok posts stay manual. No content history, reservation, intent, retry or daily-claim state is added.

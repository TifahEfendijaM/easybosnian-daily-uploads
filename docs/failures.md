# Failures and deliberate limits

notify.failure writes build/failure.txt and opens a private issue in TifahEfendijaM/easybosnian-daily-uploads. It includes the Sarajevo date, failed stage, sanitized error, actual publication status, actionable next step and actual GitHub run link, or explicitly says no run exists. Private artifacts retain safe cards/results/diagnostics for seven days. Credentials, raw model output and private answer keys are excluded.

The single workflow always writes its safe summary and attempts credential persistence after successful credential restoration. Preparation, review, fit or persistence failure prevents rendering/publication. An individual social publisher failure still allows the other independently enabled feed publishers to run. Instagram and Facebook Stories each follow their own confirmed feed publication within the current run. Failure in Instagram, including its Stories, does not suppress Facebook Stories after Facebook succeeds. Facebook Story failures keep partial returned IDs/statuses in a private result artifact and a private failure issue, without retrying or changing future runs.

No publication state, reconciliation or duplicate suppression survives. Returned post IDs and provider read-back results are stored only in the run's private artifacts. An ambiguous response may have posted successfully. Inspect the platform and the artifact before manually starting daily again; another invocation prepares replacement content and may create another post. No automatic publishing retry is sent. Read-only provider/container polling inside the current run remains.

There is no watchdog, Healthchecks, deduplicated alert table, monitor endpoint or missing-run check. If Cloudflare/GitHub never starts the run, no notification is sent. This is the user's accepted tradeoff. Cloudflare status-only dispatch logs and the private per-date cron claim remain available for manual inspection. HTTP 204 means dispatch accepted, not content or publication completed.

Turn DAILY_POSTING_ENABLED false to disable live publishing. verify and preview continue to work. If the issue API fails, the failure file and failed workflow remain available. No email delivery is claimed and no paid fallback is used.

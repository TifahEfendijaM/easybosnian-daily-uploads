# Failures and deliberate limits

notify.failure writes build/failure.txt and opens a private issue in TifahEfendijaM/easybosnian-daily-uploads. It includes the Sarajevo date, failed stage, sanitized error, actual publication status, actionable next step and actual GitHub run link, or explicitly says no run exists. Private artifacts retain safe cards/results/diagnostics for seven days. Credentials, raw model output and private answer keys are excluded.

The single workflow always writes its safe summary and attempts credential persistence after successful credential restoration. Preparation, review, fit or persistence failure prevents rendering/publication. An individual social publisher failure still allows the other independently enabled feed publishers to run. Instagram and Facebook Stories each follow their own confirmed feed publication within the current run. Failure in Instagram, including its Stories, does not suppress Facebook Stories after Facebook succeeds. Facebook Story failures keep partial returned IDs/statuses in a private result artifact and a private failure issue, without retrying. Returned known IDs are retained for a later deliberate same-date cleanup.

No publication state machine, reconciliation or publication retry is introduced. Known returned IDs are retained in publication_ids for the user's deliberate same-date cleanup. An ambiguous response without a returned ID still cannot be automatically located; inspect the account manually. A complete authenticated owned-media listing distinguishes manually deleted/expired media from a permission/network failure, which stops cleanup while independently checked replacement publishing continues. An ambiguous response may have posted successfully. Inspect the platform and the artifact before manually starting daily again; another invocation prepares replacement content and may create another post. No automatic publishing retry is sent. Read-only provider/container polling inside the current run remains.

There is no watchdog, Healthchecks, deduplicated alert table, monitor endpoint or missing-run check. If Cloudflare/GitHub never starts the run, no notification is sent. This is the user's accepted tradeoff. Cloudflare status-only dispatch logs and the private per-date cron claim remain available for manual inspection. HTTP 204 means dispatch accepted, not content or publication completed.

Turn DAILY_POSTING_ENABLED false to disable live publishing. verify and preview continue to work. If the issue API fails, the failure file and failed workflow remain available. No email delivery is claimed and no paid fallback is used.

Same-date TikTok reruns have no deletion acknowledgement gate and cannot check or delete earlier posts; remove earlier versions manually if desired. Other enabled platforms continue independently. A missing or expired Instagram deletion credential produces a cleanup warning and leaves old content; publishing still performs its separate account/kill-switch checks.

The October 3 same_words replacement confirmed all three feed posts and all Instagram image Stories. Facebook returned a photo Story with status `published` while the read-back expected `PUBLISHED`. This status-case mismatch is corrected without resubmitting the accepted Story. The regression covers both cases and rejects archived media. A failed overall run may therefore contain verified feed publications and one accepted Story; inspect platform artifacts before deliberate replacement.

Facebook replacement attempts feed-post cleanup only; Story nodes and their backing photos are never deleted by this pipeline. Existing uploaded photo IDs are preserved because they mix Story/feed assets. Failed Instagram/Facebook cleanup is a warning rather than a publication gate: record it privately with the new publication outcome, retain uncertain IDs and continue through the publisher’s independent account and kill-switch checks. No retry is added. Remove old Facebook Stories/photos and TikTok posts manually if desired. Facebook Story publication checks still accept published/PUBLISHED equivalently.

Replacement cleanup selects only the latest recorded batch on the selected Sarajevo date: the last Instagram feed post and up to three Stories recorded after it, and the last Facebook feed post. It leaves earlier same-date batches alone and never fills a partial latest Story batch with older Story IDs. D1 insertion order is exposed as recorded_order in the authenticated ID listing; provider ID sorting is not used as a clock. If order is unavailable, cleanup warns/skips and publishing remains independently gated. Facebook Stories/photos and TikTok posts stay manual. No content history, reservation, intent, retry or daily-claim state is added.

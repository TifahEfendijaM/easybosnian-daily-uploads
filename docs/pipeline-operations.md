# Pipeline operations and safeguards

This is the trusted wrapper/maintainer policy, not a content or visual-model prompt. Content, visual and recovery rules are indexed in AGENTS.md. Follow the detailed operational references linked below when working on those systems.

## Scheduling, modes and credential boundary

The existing Worker dispatches `preparation.yml` at **05:00 Europe/Sarajevo**, using controller.scheduledTime with 03:00 UTC summer/04:00 winter. Preserve the dedicated GITHUB_DISPATCH_TOKEN, exact repository-ID/owner/main identity check (public or private), status-only logging and atomic per-date preparation_dispatches claim. PREPARATION_DISPATCH_ENABLED gates starts; DAILY_POSTING_ENABLED independently gates all live entry points, including deletion. No GitHub cron, local heartbeat, catch-up or general automatic retry. The sole provider exception is the approved bounded revised-scene request after a confirmed FLUX NSFW refusal; it shares the three-total photo budget with defect repairs. Missing runs deliberately have no alert.

One workflow/job has verify (connections/workspace only; no content/history/FLUX/render/publish), preview (private stage/render; no history writes/cleanup/public exposure/publication) and daily (fresh selected content → private generation/review/render → independently gated publication). Latest preview reuses exact saved content; none/all_today previews stage a fresh private batch. Preview mode privately stores all three feed JPEGs and their Story JPEGs plus whitelisted report-source headings/prompts, so a gallery can download actual exports without publishing, saving history or creating finished-card snapshots. The existing job allows 60 minutes for bounded in-run work. The optional preview_source_batch_id input is preview-only: read the exact complete saved batch and verified originals, retain its text, create a new independent private batch, and run new photo inspection/design review/rendering. It never freezes finished designs, calls FLUX, changes the source batch, writes history, cleans up or publishes. Missing/expired/mismatched originals stop without an inference fallback. The input is rejected in verify/daily modes; empty input preserves ordinary preview behaviour. No separate reusable workflow/recovery mode or awake Mac dependency.

Use the official pinned Codex CLI and separate cloud-only managed ChatGPT authorization, stripped research environment, sandbox, structured ready/blocked result and tracked-file Git-diff guard. Only local unreviewed build drafts/private notes are writable by research. The always-run persistence step privately saves refreshed CODEX_AUTH_JSON through separate repository-restricted GH_SECRETS_TOKEN even after research fails. Persist successfully before live exposure/publication; never copy desktop sessions, expose tokens or use paid fallback. Renew only when needed with `scripts/cloud_auth_setup.py login` then save. Verification needs no proof commit/read-back. See `authorization.md` and `cloud-preparation.md`.

No reservation keys/table, generation intents, immutable package hash, GitHub content queue/save/read-back, publication state machine, optimistic concurrency, reconciliation, watchdog or Healthchecks. Manual daily reruns may publish again even after ambiguous responses; do not silently restore removed safeguards.

## Frozen batches and published-only history

History is per batch_id, with Sarajevo content date, server-assigned created_at and created_order tie-breaker. Replacement preserves creation order/date. Latest is the newest COMPLETE saved batch by creation order, not newest date/edit; metadata-only imports count for novelty but are not reuse sources. Freeze identity/date/source before research; publisher uses that identity, not its later clock. Reject ambiguous date-only routes rather than guessing.

| batch_target | Behavior |
|---|---|
| latest | reuse selected batch ID/original date, replace only it; if absent create first current-date batch without cleanup |
| none | new UUID/current-date batch, preserving all older history/posts; may reuse newest complete older source |
| all_today | new UUID/current-date batch; freeze all earlier same-date history and known-ID batches before research; prefer latest complete same-date source, otherwise older source without targeting its date |

The automatic Worker sends daily/none/new. The form exposes latest/none/all_today; today is only a deprecated Python independent-batch alias. Keep all history available during preparation/rendering for selection-aware novelty.

Stage the candidate in `build/reviewed-content.secret` (0600, ignored, excluded from artifacts), bound to exact project/batch/date/GitHub run identity. Authenticated Worker generation accepts it inline without saving history, using an independent random artwork-run cache namespace. Save history ONCE immediately after the first confirmed enabled-platform FEED publication, before later independent publishers/Stories; partial platform success still consumes novelty. Preserve fresh private artwork. No feed means no save; failure to save after publication leaves confirmed publication recorded, allows independent publishers and reports failure without republishing. Record known provider IDs immediately, even before verification/history and for partial/ambiguous outcomes.

latest overwrites only its row at that point; none adds one. all_today removes the frozen prior same-date history/artwork ONLY after replacement feed confirmation AND successful new history save. Preserve the new row, other dates and uncertain/unsupported IDs. Removal failures warn without blocking independent posting. Empty today behaves like none, never deletes yesterday. Existing older unpublished/legacy rows are not bulk-pruned. The explicitly discarded October 3 package remains excluded; historical migration 0003/0005 rollout is in `migration-and-rollout.md`/`multiple-batches.md`, never an automatic reset.

## Artwork, reuse and hosting

Use only free Cloudflare FLUX.1 Schnell, four steps. Private original/card/Story assets and results are batch-scoped with 14-day KV expiry; final public URLs are random and never expose history/answer keys. Exact retained-photo/card cache proofs and expiry follow `element-design-recovery.md`: same_image originals are not silently regenerated, snapshots bind exact source/bytes, missing/expired/altered/ambiguous sources stop before cleanup. Retained assets referenced by another batch may survive source-row pruning without extending expiry. Worker alone seals background_source/background_sources/rendered_sources; original-photo references use {batch_id,artwork_id}, with per-kind overrides for mixed reuse. Legacy original-photo imports require verified source annotations matching confirmed feeds/successful runs, never a cache-listing guess. Actions do not receive broad Cloudflare admin access.

KV is eventually consistent: pass exact rendered JPEG bytes to authenticated exposure rather than immediately rereading private upload. Require the public URL to return IDENTICAL bytes before giving it to a provider. Only explicit 404 reads may be polled for at most 180 seconds at five-second intervals; other HTTP/network errors or byte mismatches fail immediately. Never repeat writes/exposure/generation/publish to overcome consistency. Preserve private previews and expiry. See `failures.md` and `external-trigger.md`.

## Publishing and deliberate cleanup

Attempt Instagram, independently enabled Facebook and Buffer TikTok sequentially using the same three exact reviewed/rendered cards, even after another platform fails. Verify exact account/Page/channel, actual caption, carousel/photo order and provider permalink before confirming. Keep Instagram Login refresh/Stories, Facebook Page/deletion credentials and separate Facebook User carousel/poll token protected and distinct.

After successful rendering, latest cleanup targets ONLY that batch's latest recorded publication set: final Instagram feed plus at most three Story IDs FOLLOWING it, and final Facebook feed. Never delete unrelated videos/posts or every batch on its date. D1 recorded insertion order selects sets; if unavailable, warn/skip rather than infer order from IDs or fill missing Stories from earlier sets. all_today processes only its frozen same-date batch sets. none skips cleanup. Ownership/account/kill-switch checks gate deletes; complete ownership listings before treating absent IDs as missing. Authorization/network/pagination/deletion errors stop cleanup, retain uncertain IDs and warn; independent replacement publishing continues.

After each accepted Instagram DELETE, read the complete authenticated media listing once. Only confirmed absence counts as removed/forgotten. Surviving IDs or failed reads warn and retain IDs, without another DELETE. Keep date/platform/kind/object_id/account_id known-ID metadata only, not completion/intents. Facebook Stories/backing photos and published TikTok remain manual: no supported Story-delete/backing-photo workaround, Buffer cannot delete published posts, and TikTok reruns have no deletion-confirmation gate. Older mixed Facebook photo IDs are deliberately preserved. See `manual-reruns.md`, `multiple-batches.md` and `failures.md`.

Instagram feed children and parent need two consecutive FINISHED reads five seconds apart before the ONE publish request; on failure record one read-only parent status if possible. This mitigates a readiness race without promising success or authorizing publish retry.

Instagram Stories follow verified feed publication. Facebook Stories independently follow verified Facebook feed when FACEBOOK_STORIES_ENABLED/FACEBOOK_POSTING_ENABLED and the global switch permit. Reuse exact treatment-B 1080×1920 images, but upload fresh unpublished Facebook photos, not feed photo IDs; publish photo_stories and verify Page post/media identity, PUBLISHED and provider URL. Preserve confirmed partial IDs. TikTok Stories and Instagram highlights remain manual (quiz→Pitanje dana, lesson→Znaš li?, word→Riječ dana); Buffer feed is not Story publication. The unused manual TikTok export/native-reshare switch stays removed.

Native poll policy is in `instagram-polls.md`: separate Facebook User credential with verified instagram_basic/instagram_content_publish/Page read/list, ads_read and business_management, exact linked Page/profile and MANAGE/CREATE_CONTENT tasks. Attach only exact ordered 2–4 quiz options to the PARENT at creation, never slides/Stories/answer metadata. Include exact clear question in caption while preserving difficulty/footer. If Meta limits (including 25 characters/option) fail, publish WITHOUT poll and clearly report omission, never truncate/rewrite. Check attachment status and read back exact poll. Published post with failed poll remains published; no republish or live test.

Use validated integer usage/total/window, never a hardcoded limit. Fewer than three known available slots stops the set with incomplete/quota-specific reporting. Unsupported/malformed/unavailable snapshots remain unknown and preserve normal one-attempt behavior. A later refusal can contradict reported spare quota: retain quota_counter_conflict, not invented exhaustion/lower cap. Verify may probe both existing clients read-only; no token/path switch or added permission.

Preserve operation/kind, confirmed removed/already-absent counts and partial all_today results. No diagnostic deletion/publication or extra provider action. Provider diagnostics expose fixed reasons, bounded numeric/nested provider codes and per-call HTTP/exit status; no raw prose/secrets. Matching captured provider error descriptions can add fixed NSFW/content-safety, exhausted-free-allocation or temporary-capacity explanations; numeric code alone never establishes an undocumented classification. Distinguish inference, missing binding and cache failures. Bounded failed staged inference bodies (64K characters, known credentials redacted) remain only in authenticated private KV for 14 days and a 0600 runner secret file, excluded from artifacts; one protected read is not another inference attempt. Codex diagnostic extraction inspects only CLI error/turn-failed envelopes, never model messages/tool output. Export fixed reason/status/turn booleans only; private JSONL traces remain excluded.

## Reporting and rollout

`notify.failure` creates build/failure.txt with stage/date/fixed error/publication state/run link/actionable next step. Private repositories may also create a private GitHub issue; public repositories never receive detailed issues or public artifacts. The entire approved run Summary is public, including the redacted failure stage/error, numeric provider/HTTP codes, publication outcome and next step. Failure details remain visible alongside partial platform results; no generic public-error suppression applies. No free-form model/provider prose, credentials or private quiz reviews. A missing run has no watchdog alert. Never equate green CI with confirmed publication.

Successful/partial daily reports use a whitelisted snapshot of the EXACT rendering input, not mutable later history: exact FLUX prompts, difficulty, final designs/palettes, per-card layout/palette provenance, repairs/photo outcomes and confirmed links. When the repository is private, GitHub Summary has copyable prompts and Markdown/HTML/JSON copies use the existing seven-day private artifact. On public runs, the Summary also includes approved prompts, applied designs, per-card provenance and publication outcomes. Credentials, private quiz reviews/answer keys and raw model/provider traces stay excluded. Verbose prompt/design descriptions stay out of step logs; whitelisted report files are saved through the existing admin-authenticated Worker to private KV for 14 days (not content history). Recent-design context takes applied palettes/brightness from validated current rendered snapshots in the newest five retained published history rows, not arbitrary run reports. Accepted style choices are enriched only by matching, confirmed-published daily reports; deleted/superseded/unpublished designs are excluded. Private reports and legacy artifacts remain available for human audit. Preview/verify runs never become novelty/design history or consume the 15-completed-daily-report lookup; paginated workflow reads skip them before counting. Fetch a protected report locally with `python -m easybosnian.run_reports fetch --run-id ID` after loading the existing project environment. Credential files, raw traces, preparation context and answer-key packages are never archived. No Gmail/email or sending credentials. Report failure warns without undoing publication; verify/preview create no publication-success report. See `success-reports.md` and visual/recovery policy for provenance fields.

Work on a branch; show full diff and visual previews where applicable before merge. No extra live publication/deletion test, cron reset or catch-up. For actual protocol changes deploy a backward-compatible Worker FIRST, verify identity/unchanged cron/protected behavior, then merge dependent clients; follow reviewed migrations only when needed. A repository commit alone does not deploy Cloudflare. Pure prompt cleanup requires no Worker, database, schedule or credential change.

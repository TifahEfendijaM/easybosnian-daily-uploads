# EasyBosnian daily uploads

Private TifahEfendijaM/easybosnian-daily-uploads only. The existing Cloudflare Worker starts one GitHub Actions job at **05:00 Europe/Sarajevo**. It checks controller.scheduledTime against cron `0 3,4 * * *`, selecting the correct DST hour, then dispatches preparation.yml with mode=daily and batch_target=none. No GitHub schedule, automatic retry, catch-up, watchdog or Healthchecks.

A GPT agent through the existing ChatGPT subscription researches content against full private history → the trusted wrapper stages a reviewed candidate privately → Free Cloudflare FLUX backgrounds, a short visual placement review and Pillow produce three private cards → refreshed dedicated cloud credentials are persisted → Instagram, Facebook and Buffer TikTok publish independently → history is saved after the first confirmed feed → IG/FB image Stories follow their respective confirmed feed posts. No awake Mac or paid API.

## History and manual targets

Each history row has batch_id, date, created_at, theme, words/equivalents and reviewed content. Several batches may share a date. Latest is the newest complete saved batch by creation time/insertion order, with new previews excluded; editing it preserves that order. Legacy imported creation times are estimated from the available review timestamp or midnight UTC.

| batch_target | Behavior |
|---|---|
| latest (manual default) | Replace exactly the newest complete batch; keep its ID/date; attempt only its known latest IG feed/Stories and FB feed cleanup |
| none | Add a separate batch for the current Sarajevo date; preserve every existing batch/post and skip all cleanup |
| all_today | Add a replacement for the current Sarajevo date; after render, erase earlier same-date history/artwork and attempt all their supported known posts. Empty today never deletes yesterday. |

For any target choose same_words (same theme/words, fresh copy/design/images), same_theme (same theme, different words), new (new theme/words), or custom (entered theme/word/comparison/topic, or keep/delegate individual choices). none may use the latest batch as its selection source, including yesterday’s batch after midnight. Entered custom themes/words and retained choices may repeat any history, including researched corrections of manual spelling. ChatGPT-selected terms and genuinely different fallback choices must still be new against every history batch. latest overwrites only its selected content; none retains its source. The 05:00 run uses none/new and always creates that morning’s batch.

Modes remain exactly verify, preview and daily. verify checks connections/workspace without preparing/rendering/publishing. latest preview reuses exact saved content; none/all_today preview researches/renders another independent private batch without history writes or cleanup. daily always researches fresh copy according to selection and publishes after cloud-credential persistence succeeds; history is saved only after a feed publication is confirmed. New previewed content does not count in history. Read [manual controls](docs/manual-reruns.md), [the brief Bosnian guide](docs/boss-guide-bs.md) and [migration/rollout](docs/multiple-batches.md).

## Publishing and limits

DAILY_POSTING_ENABLED is checked unconditionally by live entry points; verify/preview work while false. Platforms verify their exact accounts and perform immediate provider read-back. Cleanup is best effort and does not block replacement publishing. Only known IDs from the frozen selected batch scope are eligible; Instagram uses the separate linked-Page deletion credential, Facebook deletes feed posts only. Facebook Stories/backing photos and TikTok posts are manual. Latest cleanup never deletes all posts from a date; only explicit all_today targets every frozen same-date batch. Cleanup never follows a provider ID from outside its scope or retries a publish request. Ambiguous responses can still leave duplicate posts. Missing starts produce no alert, by the user’s choice.

Private/publication metadata, generation cache, cards, Stories and local artifacts use batch_id. Public image URLs remain random with 14-day expiry; history/answer keys are private. Content rows, known IDs and the cron claim are the only durable bookkeeping; no reservation, immutable package hash, intents, generation-state rows, queue commits, reconciliation or optimistic concurrency.

Workers KV is eventually consistent. Public exposure receives the exact rendered JPEG instead of immediately rereading its private upload. Before any provider receives a fresh URL, the pipeline polls that URL's explicit 404 responses for up to three minutes and requires identical bytes. Only GET requests repeat; uploads, exposure, FLUX and social publishing are submitted once. Authentication/quota/network errors or different public bytes stop immediately. The same path covers all feed cards and Instagram/Facebook Stories. See [storage diagnostics](docs/failures.md#image-storage-visibility).

The credential-free Codex child keeps its stripped environment, workspace sandbox, structured ready/blocked contract and tracked-file diff check. It cannot publish or call protected APIs. The wrapper enforces schema, Bosnian spelling/diacritics, source/semantic review, quiz secrecy, measured text fit, shared difficulty and footer before saving. Never truncate text. Source review dates describe actual research, even when replacing an earlier content date. notify.failure retains build/failure.txt and opens a private GitHub issue with stage/date/publication status/run link; safe artifacts last seven days.

## Editorial and design

All visible copy is Bosnian. Quizzes have one objective answer and 2–4 options, including yes/no; images stay relevant and conceal only the unknown being tested. Znaš li? can cover practical facts, comparisons or topics. The post-photo reviewer chooses supported Pillow designs and one of eleven approved palettes per card. Bundled Lora/Inter, unboxed italic PRIMJER, explanation/answer treatments and measured, bounded font-size/spacing intent remain. Plan natural photographic scenes, then choose a complementary palette for Pillow; do not force unnatural colours into FLUX. Prompts are concise, photorealistic and scene-aware, without blank areas, coordinates or UI instructions.

All Stories use B: the complete photo, separate explanation/answer panels and unboxed italic example footers, with every quiz question above the photo and its choices below. Visual naming also uses B on the regular quiz slide, with the question above the full photo. Ordinary feed cards use the post-photo design catalogue. New captions end with a fresh contextual Bosnian invitation and exactly `👉easybosnian.com` on their final line; never mention deleted/replaced posts.

One shared A1–C2 difficulty is changed through [configure-level.yml](https://github.com/TifahEfendijaM/easybosnian-daily-uploads/actions/workflows/configure-level.yml), separately from publication. It persists for future preparations; retained and compatible entered words keep their individual levels. Custom entered/kept words are first corrected to their researched intended spelling where possible; invalid/incompatible seeds otherwise fall back to ChatGPT choices. Every final draft still passes all source, history, fit and secrecy checks. See docs/difficulty-policy.md.

## Successful-run reports

Successful daily runs and reruns save a private report with the exact FLUX prompts, per-card layouts, palette, difficulty and confirmed publication links. Open [daily workflow runs](https://github.com/TifahEfendijaM/easybosnian-daily-uploads/actions/workflows/preparation.yml), select the completed run, then read **EasyBosnian — successful-run report** on its **Summary** page. The three prompts have copyable code blocks. Download Markdown/HTML/JSON copies under **Artifacts** for seven days. Public report metadata is captured from the rendering input within that run, so a later replacement cannot change its prompts. Report failure warns without affecting completed uploads. Verify and preview create no publication-success report. No email credential or extra setup is required. See [access and limits](docs/success-reports.md).

Apply it once through Wrangler; never replay migration 0003 or recover discarded packages. Legacy date-only reads remain available; ambiguous date-only writes/generation/publication access refuse to guess. New code uses explicit batch paths. Require checks, finish the protected maintenance sequence, read back live schema/bundle/clock and restore the existing kill switch. No automatic live test is dispatched. See [exact rollout and data limits](docs/multiple-batches.md).

New captions mention their actual lesson difficulty naturally in Bosnian prose, using a truthful range for mixed levels; retained unknown ratings stay unknown. The contextual website invitation remains last. all_today keeps unsupported/uncertain publication IDs for cleanup only; Facebook Stories/photos and TikTok posts still require manual removal. Preview never performs cleanup or erases history.

Instagram cleanup checks the complete authenticated media listing once after each accepted DELETE. A surviving ID or failed read produces a cleanup warning and keeps that ID; it never repeats the DELETE, and replacement publishing continues independently. Only confirmed absence is counted as removed and forgotten. This is a read within the current attempt, without publication state, retries or a new schedule.


## Photo-assessed declarative visual contract

After FLUX generates the natural photographs, one read-only ChatGPT review selects approved designs, palettes, independent block positions and bounded typography. The trusted catalogue now also includes three-rounded-corner `soft_corner` panels and answer-only `folded_corner` slips. Blocks can independently choose approved ink/paper/accent text and surface combinations and any numeric surface opacity from 50% to 100%, chosen deliberately for the photograph and readability. Photographic title/example text can use white-on-black, black-on-white or approved palette text/fade colour pairs. Fade shape, size, edges and contrast-driven strength retain the original renderer presets; the model controls only their colour pairing. No custom drawing code, fonts, arbitrary colours or fade alpha are accepted. The blue/yellow logo experiment remains off.

Pillow preserves exact Bosnian copy and diacritics, loads the fonts, measures wrapping, occupied bounds and actual composited glyph contrast. It protects header/logo/photo regions and reading order. A position-only mistake first gets a bounded nearest-candidate translation search that preserves widths, styles, typography, colours and opacity. Every adjusted result is measured and rendered again; the summary records requested/applied coordinates as **ChatGPT with Pillow placement adjustments**. Valid proposals are never moved for aesthetics. Unsupported, unreadable or impossible proposals still require the existing safe fallback, independently of palette fallback. No extra model, image generation or publishing retry is added.

Each photograph gets its own suitable palette. For `terracotta-sand`, three uses among the last nine known rendered images triggers alternatives-first selection, including earlier choices in the current batch. The model may reuse it only with an explicit no-other-suitable-palette exception. Usage comes from bounded recent private run artifacts and can be incomplete when older artifacts are unavailable; unknown data is never invented. Ordinary quizzes should consider four well-researched choices more often, while genuine binary/yes-no questions retain two and three remains available when appropriate. Stories keep treatment B. See [the full visual contract](docs/visual-style-contract.md) for all approved controls and safeguards.

### Reuse photos with new content

Choose daily → same_images to keep the selected saved batch’s theme, words and original photos while preparing new text, caption, palette/design choices and post/Story cards. Choose latest to replace it, none to add another independent batch, or all_today for the existing same-date cleanup behavior. Custom fields do not apply. This sends no FLUX requests. Original photos must still exist in the 14-day private cache and have an explicitly recorded source (older batches require a verified source annotation); otherwise it stops before deletion, and same_words remains the option for newly generated photos. Every new saved batch records the exact source photograph reference for later reuse. No original photo is inferred from a social upload.

The summary reports whether recent design history was available and how many accepted run records were supplied. Each photo still receives an independently selected suitable palette, subject to the alternatives-first terracotta-sand rule; no random rotation is used. A repeated ID alone does not mean fallback.

Before selecting a final composition, the reviewer must compare every approved palette and all compatible design choices. Catalogue order is not a ranking, and the first acceptable, last-listed or familiar option must not end the comparison. The existing three-in-nine terracotta-sand rule remains.
